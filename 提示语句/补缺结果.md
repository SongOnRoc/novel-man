# Novel-Man 前端项目差距分析报告

**分析时间:** 2025年7月12日
**分析员:** NexusCore

## 1. 分析背景

本次分析旨在通过比对项目历史开发文档 (`开发步骤/前端/step*.md`)、最终用户需求 (`需求文档/用户需求.md`) 与当前项目的实际文件结构，找出功能上的遗漏和差距，为后续的“查漏补缺”开发工作提供明确指引。

## 2. 分析方法

1.  **需求基准:** 以 `需求文档/用户需求.md` 中定义的 `V1.0 (MVP)` 功能为最终目标。
2.  **实现梳理:** 结合所有 `step*.md` 文档内容和 `frontend/src` 目录结构，确认已开发和已存在的功能模块。
3.  **差距识别:** 逐项对比需求与实现，识别出未实现、部分实现或未集成集成的功能点。

## 3. 主要功能差距

根据综合分析，当前项目存在以下核心及重要功能差距，按优先级排序如下：

### P0 - 核心功能缺失 (严重影响核心体验)

1.  **编辑器 - 查找替换功能**
    *   **问题描述:** `用户需求.md` 中明确要求的编辑器核心功能，但在所有开发步骤中均未提及，代码结构中也无相关组件。这是文本编辑器的基础功能，当前缺失。
    *   **技术建议:** 需要在 Tiptap 编辑器中实现查找与替换的 UI 和逻辑。可以利用 Tiptap 的现有扩展或自定义实现。

2.  **设定速查功能集成**
    *   **问题描述:** `SettingsLookup.tsx` 组件已创建，但开发步骤 `step21.md` 为空，表明该功能的实现和集成工作被跳过。导致用户在写作时无法快速查阅已创建的角色和世界观设定，这是产品的核心价值主张之一。
    *   **技术建议:** 实现 `SettingsLookup.tsx` 的内部逻辑（API调用、数据显示），并将其作为侧边栏或浮动面板集成到编辑器页面中，与编辑器内容进行交互。

### P1 - 重要功能缺失 (影响功能完整性)

3.  **角色关系网络**
    *   **问题描述:** `用户需求.md` 中要求的功能，但在开发步骤中未规划，代码中也缺少相应的可视化组件来展示和编辑角色之间的关系。
    *   **技术建议:** 引入一个图形/网络可视化库（如 `react-flow` 或 `d3.js`），创建专门的 UI 界面来管理和展示角色关系图谱。

4.  **图片上传与管理**
    *   **问题描述:** 角色和世界观设定需要图片/头像支持，但目前缺少通用的图片上传组件、前端预览逻辑以及后端存储和处理的服务对接。
    *   **技术建议:** 创建一个可复用的图片上传组件（支持预览、大小限制），并定义相应的后端 API 接口来处理图片存储。

### P2 - 用户体验优化 (影响使用流畅度)

5.  **统一的用户偏好设置页面**
    *   **问题描述:** 当前仅有零散的设置项（如编辑器主题），缺少一个集中的“设置”页面来统一管理用户的所有偏好（如界面、AI 行为、通知等）。
    *   **技术建议:** 创建一个新的路由页面 `(main)/settings`，并在其中整合所有用户可配置的选项。

6.  **前端数据同步逻辑**
    *   **问题描述:** 当前的数据保存依赖于用户操作触发，缺少明确的、自动的跨设备数据同步机制和状态提示（如“正在同步...”、“已同步”）。
    *   **技术建议:** 考虑使用 `SWR` 或 `React Query` 的高级功能（如 revalidate on focus）来模拟自动同步，并在 UI 上增加明确的同步状态指示器。

### P3 - 待验证项

7.  **自动保存机制**
    *   **问题描述:** `step12.md` 中提到了自动保存，但其实现的健壮性（例如，如何处理离线编辑、网络恢复后的数据合并或冲突解决）需要通过代码审查来进一步确认。
    *   **技术建议:** 对 `components/editor/TiptapEditor.tsx` 和相关 hooks 进行代码审查，确认其自动保存逻辑的完整性和可靠性。

## 4. 后续步骤建议

建议与用户沟通，根据以上差距报告确定“查漏补缺”的开发优先级，然后创建新的开发任务，逐一实现缺失的功能。
