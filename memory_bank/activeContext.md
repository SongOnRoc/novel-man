## [2025-07-18] 实现生产级日志模块 (最终版 - 完全热更新)

### 任务概述
根据 `requirements/logger-spec.md` 技术规范，实现一个生产级的日志模块。

### 最终实现细节
经过多次迭代和澄清，最终根据用户的明确指示，实现了功能完整且设计清晰的最终版本：

1.  **完全热更新**:
    *   通过集成 `viper` 的 `WatchConfig` 和 `fsnotify`，实现了对 `config.yaml` 的实时监控。
    *   当 `debug` 或 `console_log` 开关在运行时被修改，日志系统会通过回调函数**立即、动态地**切换日志的输出格式（增加/移除 `caller`）和输出目标（增加/移除控制台输出），**无需重启服务**。

2.  **解耦设计**:
    *   通过在 `config` 包中定义回调函数，并在 `logger` 包中注册实现，成功解除了 `config` 与 `logger` 之间的循环依赖。

3.  **精确格式与内置 Trace ID**:
    *   **格式**: 所有输出都严格遵循 `[时间][LEVEL][traceid] message` (标准模式) 和 `[时间][LEVEL][traceid][文件名:行号] message` (Debug 模式)。
    *   **Trace ID**: 在包加载时，会生成一个基于**纳秒时间戳**的根 `trace_id`。

4.  **健壮性**:
    *   使用 `sync.Once` 彻底解决了并发初始化问题。
    *   在创建日志实例时，会自动创建不存在的目录和文件。

### 结论
最终的日志模块设计清晰，不仅支持灵活的实例创建和精确的格式控制，还实现了对所有相关配置（`debug` 和 `console_log`）的**完全热更新**功能，同时保证了代码结构的健壮和高内聚。
