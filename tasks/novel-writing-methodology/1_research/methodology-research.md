# 小说创作方法论调研：作家构思思路与创作流程资料汇总

> 产出文件：[`tasks/novel-writing-methodology/1_research/methodology-research.md`](tasks/novel-writing-methodology/1_research/methodology-research.md)

## 摘要
本调研汇总了多种主流小说创作方法论/结构模型（结构类与流程类并重），并将其抽象为「从灵感→概念→大纲→细纲（场景/章节）→初稿→修订」的通用工作流。最后给出对 `novel-man`（结构化写作 + 世界观构建 + AI 辅助 + 无干扰编辑）产品形态的 UI/交互启示：**用“方法论模板 + 分步工单 + 可视化进度/缺口提示”把创作过程外化**，同时允许“发现式写作”的弹性回填。

---

## 1. 主流创作方法论综述（3–5 种+）

> 说明：方法论可粗分为两类：
> - **结构模型（Structure Models）**：告诉你“故事宏观形状应该像什么”（如三幕、英雄之旅、Save the Cat）。
> - **流程/产物模型（Process / Artifact Models）**：告诉你“从一个点子逐步产出哪些写作工件”（如雪花法）。

### 1.1 三幕剧结构（Three-Act Structure）——最常用的宏观骨架
**核心思想**：故事可分为三大段：
1) 第一幕 Setup（建立人物/世界/核心问题）；
2) 第二幕 Confrontation（冲突升级、困难加码、转折不断）；
3) 第三幕 Resolution（危机/高潮/结局，回收线索）。

**优点**：简单、可迁移、可与其他方法叠加（如 Save the Cat 的 15 beats 可视作三幕的细化）。

**适合**：需要一个“足够通用”的骨架；或者产品侧希望提供**最基础的结构模板**。

来源：NovelPad 的结构简介指出三幕剧常被用于小说/编剧 [1]；澎湃新闻进一步说明三幕剧可追溯到古希腊亚里士多德《诗学》[2]；知乎专栏对三幕式结构做了详细解释 [12]；微信读书《拆解一切故事写作》提供了经典三幕剧结构的实践指导 [13]。

### 1.2 英雄之旅（Hero’s Journey / Monomyth）——以“角色成长”驱动的结构模板
**核心思想**：用一组常见阶段描述主角从“日常世界”进入“非常世界”，经历试炼、蜕变并归来。常见版本会包含“召唤、拒绝、导师、跨越门槛、试炼、深渊、奖励、归途、复活、归来”等阶段。

**优点**：对“人物弧光/成长”提示强；对奇幻、冒险、成长类作品特别友好。

**适合**：希望 UI 能跟踪“角色弧光/阶段推进”的写作者；也适合作为 AI 辅助生成“缺失阶段提醒”的结构框架。

来源：MasterClass 对英雄之旅概念与写作应用做了入门解释 [3]。

### 1.3 Save the Cat（“救猫咪”写作节拍）——三幕的“节拍表（Beat Sheet）”细化
**核心思想**：在三幕的大框架上，提供更细颗粒的节拍（常见说法为 15 beats）来约束节奏与转折位置，并显式提醒 B 故事（副线）在第二幕中的位置。

**优点**：对“节奏感/转折密度”有强提示；适合做 UI 上的**节拍清单**与进度条。

**适合**：偏 plotter（爱规划）的人；或写作者希望对“每个关键节点该出现什么功能”有提示。

来源：NovelPad 的综述文章将 Save the Cat 描述为对三幕结构的扩展 [1]。

### 1.4 雪花法（Snowflake Method）——从“一句话”递归扩写到场景清单
**核心思想**：把写小说拆成一系列可交付的工件，从最小的故事核开始逐步扩写，常见步骤包括：
- 1 句概括 → 1 段概括 → 人物摘要表 → 扩写每句为段落 → 主要人物一页简介 → 四页梗概 → 角色表格 → 场景列表 → 场景描述 → 开始初稿。

**优点**：高度“可产品化”（每一步都是明确的输入输出）；天然适合 UI 做**分步向导/任务列表**。

**适合**：希望把灵感落地为结构化产物的写作者；也适合将 AI 能力嵌入每一步（例如自动生成“角色动机缺口”“冲突不足”等提示）。

来源：The Wordling 的文章给出雪花法 10 步及其为什么有效 [4]；知乎专栏详细解释了“由简入繁、逐步扩展”的核心思想 [5]；百度文库提供了雪花写作法的系统创作方法 [11]；艺术论博客对雪花创作法做了完整介绍 [15]。

### 1.5 弗莱塔格金字塔（Freytag's Pyramid）——经典戏剧的五幕结构
**核心思想**：由德国剧作家古斯塔夫·弗莱塔格（Gustav Freytag）在 1863 年提出，将故事划分为五个阶段，形成金字塔形状：

1. **铺垫（Exposition）**：介绍背景、人物、初始情境
2. **上升动作（Rising Action）**：冲突逐步升级，推动故事发展
3. **高潮（Climax）**：故事的最高张力点，转折点
4. **下降动作（Falling Action）**：高潮后的后果展开，走向结局
5. **结局（Denouement）**：冲突解决，新平衡建立

**优点**：强调故事的戏剧张力曲线，特别适合悲剧和传统戏剧结构。

**适合**：需要理解“张力曲线”的写作者；适合做 UI 上的**故事节奏可视化**。

来源：Wikipedia 对故事结构词条的总结指出，弗莱塔格金字塔是戏剧结构的经典模型之一 [6]。

### 1.6 七点故事结构（Seven-Point Story Structure）——以“转折点”为核心
**核心思想**：由科幻作家丹·威尔斯（Dan Wells）推广，将故事简化为七个关键转折点：

1. **钩子（Hook）**：主角的初始状态，与结局形成对比
2. **转折点 1（Plot Turn 1）**：推动主角进入故事核心冲突
3. **夹点 1（Pinch 1）**：压力施加，对手力量显现
4. **中点（Midpoint）**：主角从被动反应转为主动行动
5. **夹点 2（Pinch 2）**：压力最大化，看似无望
6. **转折点 2（Plot Turn 2）**：获得最终胜利所需的关键信息/物品
7. **结局（Resolution）**：故事终点，与钩子形成呼应

**优点**：简洁明了，七个点即可勾勒完整故事弧；特别适合**从结局倒推**的写作方式。

**适合**：喜欢“先定终点再规划路径”的写作者；UI 上可做**七个节点的清单/时间线**。

来源：Writer's Digest、K.M. Weiland 等写作教学资源对七点结构的普及介绍 [7]；Reedsy 博客提供了详细步骤说明 [8]。

### 1.7 Dan Harmon 故事圆（Story Circle）——“角色变化”的八步模型
**核心思想**：由《瑞克和莫蒂》创作者丹·哈蒙（Dan Harmon）提出，将故事简化为八个步骤，强调角色的变化弧线：

1. **You（你）**：主角处于舒适区
2. **Need（需要）**：主角想要某样东西
3. **Go（出发）**：主角进入不熟悉的情境
4. **Search（寻找）**：适应并寻找
5. **Find（找到）**：找到想要的，但付出代价
6. **Take（取走）**：付出代价，取走所需
7. **Return（返回）**：回到熟悉的情境
8. **Change（改变）**：主角已经改变

**优点**：极简但普适，适用于任何长度和类型的故事；强调“角色内在变化”而非外部情节。

**适合**：希望保证“角色弧光”完整的写作者；UI 上可做**环形可视化进度**。

来源：Dan Harmon 的博客和 Channel 101 教学资源 [9]。

### 1.8 其它常见结构/方法（可作为扩展模板库）
除上述方法外，还有更多可选框架，如：
- **Fichtean Curve（菲希特曲线）**：一系列危机串联，无传统铺垫
- **Kishōtenketsu（起承转合）**：东亚四段式结构，不依赖冲突驱动
- **Michael Hauge's 6-Stage Plot Structure**：六阶段结构，强调内在与外在旅程

来源：NovelPad 的文章在“其他方法”部分列举了多种结构模型 [1]。

## 2. 灵感→大纲→细纲→结构化情节：通用创作流程抽象

将多种方法论抽象后，可以得到一个对大多数小说都适用的“工件流水线”（Artifacts Pipeline）：

### 2.1 阶段 A：灵感捕获（Idea Capture）
**输入**：零碎灵感（设定、角色、画面、金手指、冲突点、主题句）。

**关键动作**：
- 把灵感落地为“可检索的碎片”（tag、体裁、情绪、冲突类型）。
- 允许不完整：先记录，再在后续阶段“逼近成形”。

**产物**：Idea 卡片/灵感库（可带附件、引用、随手笔记）。

### 2.2 阶段 B：概念凝结（Premise / Logline）
对应雪花法 Step1/Step2 的思想：
- **一句话概括**：谁（主角）想要什么（目标）但被什么阻止（阻力/对手），失败的代价是什么（stakes）。
- **一段话概括**：把开端-升级-结局压缩成一段，形成“主线故事问题”。

**产物**：logline、premise、主题/核心命题、读者承诺（genre promise）。

### 2.3 阶段 C：宏观结构（Macro Outline / Beats）
选一个结构框架来“钉节点”：
- 三幕：关键转折点（进入第二幕/中点/进入第三幕/高潮）
- 英雄之旅：阶段推进与“成长门槛”
- Save the Cat：节拍表（beats）

**产物**：宏观结构卡（节点清单 + 每节点一句话说明）。

### 2.4 阶段 D：梗概与人物工程（Synopsis + Character Engineering）
把“节点”扩写成更连贯的梗概，同时补足人物：
- 主要人物：欲望（Want）/需求（Need）、缺陷、恐惧、价值观、转变点
- 对手/反派：其目标与主角目标“对撞”的方式
- 关系网：盟友、导师、羁绊、背叛点

**产物**：1–4 页梗概、人物卡、人物弧光、关系图。

### 2.5 阶段 E：细纲（Scene/Chapter Outline）
从“梗概”进入“可写的单位”：
- 章节级：每章目标、信息增量、转折/悬念、与主线/副线对应
- 场景级：场景目标（Goal）-冲突（Conflict）-结果（Outcome/Disaster），以及情绪曲线

雪花法在后期强调“场景列表→场景描述”，就是把细纲工件显式化。Bilibili 专栏提供了网文写作从灵感到大纲到卷纲的全流程指南 [10]。

**产物**：章节清单、场景清单、每场景简述/卡片、时间线。

### 2.6 阶段 F：初稿（Drafting）与阶段 G：修订（Revision）
- 初稿阶段更重“连续产出”，允许偏离大纲但要能回填（回写到场景卡/章节卡）。
- 修订阶段更重“结构一致性”和“阅读体验”：节奏、悬念、信息投放、角色一致性。

**产物**：草稿版本、修订清单（问题→定位→修改→验证）。

## 3. 作家常用构思技巧与工具（可落地为产品功能点）

### 3.1 构思技巧清单（Techniques）
1) **What-if 变体法**：对一个核心设定不断提出“如果……会怎样”，生成冲突链。
2) **冲突升级阶梯**：把阻力按强度排列，从外部阻力→关系阻力→内在阻力层层加码。
3) **主角三件套**：目标（Goal）/动机（Motivation）/代价（Stakes）。缺一则剧情容易飘。
4) **对手镜像法**：反派/对手的价值观与主角形成镜像或互补，冲突更“必然”。
5) **场景 G-C-O 模板**（Goal-Conflict-Outcome）：每场景都要有推进；否则容易“写得很热闹但剧情不动”。
6) **信息投放与悬念管理**：每章至少一个“新信息/新问题/新威胁”，形成阅读牵引。
7) **人物弧光节点**：把人物转变拆成可观察的行为证据（不是口号式成长）。
8) **主题校验**：每个关键节点问一次：它是否在压力下迫使人物做“主题相关选择”？
9) **副线功能化**：副线为主线服务（对照主题、提供资源、制造误导、补足情感）。
10) **约束生成法**：先设定约束（地点封闭、时间倒计时、资源稀缺），再让剧情在约束中自洽生长。

### 3.2 常用“工件化工具”（Artifacts）
- **灵感库/碎片箱**：可随手记、可标签化、可快速归档到作品。
- **人物卡/关系图**：人物属性 + 欲望/恐惧/缺陷 + 关系边。
- **结构模板**：三幕/英雄之旅/节拍表等。
- **章节表/场景卡**：列表 + 卡片看板（拖拽排序）。
- **时间线**：按故事内时间排列事件，尤其适合多线叙事。

## 4. 对 novel-man 的 UI/交互设计启示（结合项目定位）

> novel-man 核心价值：结构化写作、世界观构建、AI 辅助、无干扰编辑。
> 因此 UI 的目标不是“强迫所有人用一种方法”，而是：
> **提供多方法论的“可选模板” + 把写作过程外化为“可交付工件” + 允许发现式写作回填**。

### 4.1 信息架构建议：以“工件（Artifacts）”为中心，而非以“页面（Pages）”为中心
建议对每部作品（Work）建立统一的创作空间：
- 灵感（Ideas）
- 结构（Structure / Beats）
- 人物（Characters）
- 世界观（Worldview：地点/设定/规则）
- 大纲（Outline：梗概/章节/场景）
- 草稿（Drafts / Chapters）

这样可以把雪花法、三幕、英雄之旅都映射到同一套工件体系。

### 4.2 “方法论模板库”与“分步向导”的产品形态
**模板库（多选一或叠加）**：
- 三幕剧模板（关键节点表）
- 英雄之旅模板（阶段清单）
- Save the Cat 节拍表（beats checklist）
- 雪花法 10 步向导（每步一个表单/生成器）

**分步向导（Wizard）**：
- 每一步清楚定义“输入字段 + 生成输出 + 质量检查（可选）”。
- 允许跳步、允许回填，避免阻塞创作。

与 AI 辅助结合方式：
- 每一步提供“AI 检查”按钮：例如检查 premise 是否缺 stakes，人物动机是否薄弱。
- 提供“多候选生成”：避免单一答案绑架创作。

### 4.3 细纲落地：用“章节/场景卡片 + 拖拽排序 + 缺口提示”支持结构化推进
**场景卡建议字段**：
- 场景目标/冲突/结果（G-C-O）
- POV 角色、地点、时间
- 关联人物/设定
- 情绪曲线（可选）

**缺口提示**（非强制，作为“结构健康度”）：
- 是否存在“长时间无转折/无新信息”区段
- 是否缺少中点/危机/高潮对应卡
- 某人物出场间隔过长、动机线断裂

### 4.4 无干扰写作与结构化写作的折中：Focus Mode + 侧边工件
- 编辑器主区保持干净。
- 右侧/抽屉式 Side Panel 作为“工件引用区”：
  - 当前章节关联的场景卡
  - 角色卡快速查阅
  - 世界观条目快速插入
  - 结构节点（本章处于第几幕/第几节拍）提示

### 4.5 世界观与结构的联动：把“设定一致性”变成产品优势
当写作者在场景卡/章节中引用地点、设定规则、道具时：
- 自动建立引用关系（反向链接）
- 提醒设定冲突（例如时间线不一致、人物年龄不一致）

### 4.6 推荐落地的最小可行功能（MVP+）
1) 方法论模板库（先做三幕 + 雪花法，覆盖面最大）
2) 章节清单 + 场景卡（拖拽排序）
3) 灵感箱（快速记录 + 一键转为场景/角色/设定）
4) AI 辅助：premise 检查、场景卡补全、节拍缺口提示（可选）
