# 后端技术设计方案

## 1. 概述

本文档描述了 novel-man 项目的后端技术设计方案。后端采用 Go 语言开发，使用 Gin Web 框架构建 RESTful API，通过 GORM ORM 框架与数据库交互，实现了一个功能完整的小说创作和管理系统。

## 2. 技术栈

- **编程语言**: Go
- **Web 框架**: Gin
- **ORM 框架**: GORM
- **数据库**: MySQL/PostgreSQL/SQLite
- **配置管理**: Viper
- **命令行接口**: Cobra
- **身份验证**: JWT
- **日志系统**: 自定义日志系统（基于 lumberjack）
- **测试框架**: testify, goconvey

## 3. 架构设计

### 3.1 整体架构

后端采用分层架构模式，分为以下层次：

```
┌─────────────────────────────────────┐
│              API 层                 │
│  (处理 HTTP 请求和响应)             │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            路由层                   │
│  (URL 路由映射和中间件处理)         │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            服务层                   │
│  (业务逻辑处理和数据转换)           │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            数据访问层               │
│  (数据库操作和 ORM 映射)            │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            数据库层                 │
│  (数据持久化存储)                   │
└─────────────────────────────────────┘
```

## 4. 核心组件设计

### 4.1 路由层

路由层使用 Gin 框架实现，负责将 HTTP 请求映射到相应的处理函数。路由按功能模块组织，每个模块有独立的路由组。

关键特性：
- 使用 JWT 中间件进行身份验证
- 使用自定义中间件进行权限控制
- 支持 API 版本控制

### 4.2 服务层

服务层包含业务逻辑处理，每个功能模块都有对应的服务实现。

关键特性：
- 业务逻辑与数据访问分离
- 使用事务确保数据一致性
- 实现数据验证和错误处理

### 4.3 数据访问层

数据访问层使用 GORM ORM 框架实现，提供对数据库的访问接口。

关键特性：
- 支持多种数据库（MySQL、PostgreSQL、SQLite）
- 使用连接池提高性能
- 实现数据库迁移功能

### 4.4 认证授权

认证授权使用 JWT 实现，支持用户注册、登录和权限验证。

关键特性：
- 使用 bcrypt 进行密码哈希
- JWT 令牌有效期为 72 小时
- 支持令牌刷新机制

### 4.5 日志系统

日志系统基于 lumberjack 实现，支持日志轮转和压缩。

关键特性：
- 支持多级别日志记录（DEBUG、INFO、WARN、ERROR）
- 支持控制台和文件输出
- 支持动态配置更新
- 使用 trace ID 追踪请求链路

### 4.6 配置管理

配置管理使用 Viper 实现，支持多种配置格式和环境变量。

关键特性：
- 支持 YAML 配置文件
- 支持环境变量覆盖
- 支持配置热更新

## 5. 数据模型设计

### 5.1 核心实体

- **User**: 用户实体，包含基本信息和认证信息
- **Work**: 作品实体，包含作品的基本信息和关联内容
- **Chapter**: 章节实体，包含章节内容和相关信息
- **Draft**: 草稿实体，包含未发布的章节内容
- **Character**: 角色实体，包含角色的基本信息和详细描述
- **WorldviewCategory**: 世界观分类实体
- **WorldviewItem**: 世界观条目实体

### 5.2 关联关系

- **Work-Chapter**: 一对多关系，一个作品包含多个章节
- **Work-Draft**: 一对多关系，一个作品包含多个草稿
- **Work-Character**: 多对多关系，一个作品可以包含多个角色，一个角色可以属于多个作品
- **Work-WorldviewItem**: 多对多关系，一个作品可以包含多个世界观条目，一个世界观条目可以属于多个作品
- **Character-WorldviewItem**: 多对多关系，角色和世界观条目之间可以建立关联

## 6. API 设计

### 6.1 认证相关

- `POST /api/v1/auth/register`: 用户注册
- `POST /api/v1/auth/login`: 用户登录
- `GET /api/v1/auth/me`: 获取当前用户信息

### 6.2 作品管理

- `POST /api/v1/works`: 创建作品
- `GET /api/v1/works`: 获取作品列表
- `GET /api/v1/works/:id`: 获取作品详情
- `PUT /api/v1/works/:id`: 更新作品
- `DELETE /api/v1/works/:id`: 删除作品

### 6.3 章节管理

- `POST /api/v1/chapters`: 创建章节
- `GET /api/v1/chapters`: 获取章节列表
- `GET /api/v1/chapters/:id`: 获取章节详情
- `PUT /api/v1/chapters/:id`: 更新章节
- `DELETE /api/v1/chapters/:id`: 删除章节

### 6.4 角色管理

- `POST /api/v1/characters`: 创建角色
- `GET /api/v1/characters`: 获取角色列表
- `GET /api/v1/characters/:id`: 获取角色详情
- `PUT /api/v1/characters/:id`: 更新角色
- `DELETE /api/v1/characters/:id`: 删除角色

## 7. 安全设计

### 7.1 身份验证

- 使用 JWT 进行身份验证
- 密码使用 bcrypt 进行哈希存储
- 支持 HTTPS 加密传输

### 7.2 权限控制

- 使用中间件进行权限验证
- 实现基于角色的访问控制
- 防止越权访问

### 7.3 数据安全

- 敏感信息加密存储
- SQL 注入防护
- XSS 防护

## 8. 性能优化

### 8.1 数据库优化

- 使用索引提高查询性能
- 实现分页查询避免大数据量传输
- 使用连接池减少连接开销

### 8.2 缓存策略

- 实现内存缓存减少数据库访问
- 使用 Redis 进行分布式缓存（未来扩展）

### 8.3 并发处理

- 使用 Goroutine 提高并发处理能力
- 实现限流防止系统过载

## 9. 测试策略

### 9.1 单元测试

- 使用 testify 进行单元测试
- 覆盖核心业务逻辑
- 使用内存数据库进行数据访问层测试

### 9.2 集成测试

- 使用 E2E 测试验证 API 功能
- 使用 goconvey 进行行为驱动测试
- 实现自动化测试流程

## 10. 部署方案

### 10.1 环境配置

- 支持 Docker 容器化部署
- 使用环境变量配置不同环境
- 实现配置文件热更新

### 10.2 监控和日志

- 实现健康检查接口
- 集成 Prometheus 监控
- 使用 ELK 进行日志分析（未来扩展）

## 11. 维护和扩展

### 11.1 代码维护

- 遵循 Go 语言编码规范
- 实现代码审查流程
- 使用 Git 进行版本控制

### 11.2 功能扩展

- 模块化设计便于功能扩展
- 使用插件机制支持第三方集成
