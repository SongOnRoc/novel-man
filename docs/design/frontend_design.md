# 前端技术设计方案

## 1. 概述

本文档描述了 novel-man 项目的前端技术设计方案。前端采用 Next.js 框架构建，使用 React 实现组件化开发，通过 TypeScript 提供类型安全，使用 Tailwind CSS 实现响应式设计，构建了一个功能完整的小说创作和管理系统用户界面。

## 2. 技术栈

- **核心框架**: Next.js 14 (App Router)
- **核心库**: React 18
- **语言**: TypeScript
- **样式**: Tailwind CSS
- **组件库**: shadcn/ui
- **状态管理**: React Query (TanStack Query)
- **HTTP客户端**: Axios
- **表单处理**: React Hook Form
- **路由**: Next.js 内置路由
- **构建工具**: Next.js 内置编译和打包

## 3. 架构设计

### 3.1 整体架构

前端采用分层架构模式，分为以下层次：

```
┌─────────────────────────────────────┐
│              UI 层                  │
│  (页面组件和UI展示)                 │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            逻辑层                   │
│  (业务逻辑和状态管理)               │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            数据层                   │
│  (API调用和数据获取)                │
└─────────────────────────────────────┘
                  │
┌─────────────────────────────────────┐
│            服务层                   │
│  (后端API服务)                      │
└─────────────────────────────────────┘
```

### 3.2 目录结构

```
frontend/
├── app/                    # 应用页面目录 (Next.js App Router)
│   ├── (auth)/            # 认证相关页面
│   ├── (main)/            # 主要功能页面
│   ├── api/               # API路由 (BFF层)
│   └── layout.tsx         # 全局布局
├── components/            # 可复用组件
│   ├── ui/                # UI基础组件 (shadcn/ui)
│   └── common/            # 通用业务组件
├── hooks/                 # 自定义Hook
│   ├── work/              # 作品相关Hook
│   ├── chapter/           # 章节相关Hook
│   └── auth/              # 认证相关Hook
├── lib/                   # 工具库
│   ├── api/               # API客户端
│   └── utils/             # 工具函数
├── types/                 # TypeScript类型定义
│   ├── work/              # 作品相关类型
│   ├── chapter/           # 章节相关类型
│   └── auth/              # 认证相关类型
└── public/                # 静态资源
```

## 4. 核心组件设计

### 4.1 页面架构

使用 Next.js App Router 实现页面路由，采用基于文件系统的路由结构。

关键特性：
- 支持动态路由
- 实现嵌套路由
- 支持路由守卫
- 支持服务端渲染和静态生成

### 4.2 组件设计

采用组件化设计，将UI拆分为可复用的组件。

关键特性：
- 原子化设计原则
- 组件状态管理
- 组件通信机制
- 组件样式隔离

### 4.3 状态管理

使用 React Query 进行服务端状态管理，使用 React Context 进行客户端状态管理。

关键特性：
- 自动缓存和更新
- 后台数据同步
- 错误重试机制
- 加载状态处理

### 4.4 数据获取

使用 Axios 进行 HTTP 请求，通过自定义 API 客户端统一处理请求和响应。

关键特性：
- 请求拦截器
- 响应拦截器
- 错误处理
- 认证令牌管理

### 4.5 API代理

实现 Next.js API 路由作为 BFF（Backend for Frontend）层，代理前端请求到后端服务。

关键特性：
- 解决 CORS 问题
- 统一 API 入口
- 请求转发和响应处理
- 错误处理和日志记录

## 5. UI/UX设计

### 5.1 设计系统

使用 Tailwind CSS 实现设计系统，确保UI的一致性。

关键特性：
- 响应式设计
- 主题定制
- 组件样式复用
- 设计规范遵循

### 5.2 组件库

使用 shadcn/ui 作为基础组件库，提供丰富的UI组件。

关键特性：
- 可访问性支持
- 主题定制能力
- 组件可组合性
- 文档完善

### 5.3 用户体验

注重用户体验设计，提供流畅的交互体验。

关键特性：
- 加载状态反馈
- 错误状态处理
- 用户操作确认
- 无障碍访问支持

## 6. 类型安全

使用 TypeScript 提供全面的类型安全。

关键特性：
- 静态类型检查
- 类型推断
- 接口和类型别名
- 泛型支持

## 7. 性能优化

### 7.1 代码分割

使用 Next.js 自动代码分割功能，按需加载页面和组件。

### 7.2 图片优化

使用 Next.js 内置图片优化功能，自动优化图片大小和格式。

### 7.3 数据缓存

使用 React Query 实现数据缓存，减少重复请求。

### 7.4 静态生成

使用 Next.js 静态生成功能，提高页面加载速度。
