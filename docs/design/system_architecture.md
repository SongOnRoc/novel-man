# 系统架构设计方案

## 1. 概述

本文档描述了 novel-man 项目的整体系统架构设计方案，整合了前端和后端的设计，提供了一个完整的系统视图。该系统是一个用于小说创作和管理的全栈应用程序，采用现代化的技术栈和架构模式构建。

## 3. 技术架构

### 3.1 前端技术栈

- **核心框架**: Next.js 14 (App Router)
- **核心库**: React 18
- **语言**: TypeScript
- **样式**: Tailwind CSS
- **组件库**: shadcn/ui
- **状态管理**: React Query (TanStack Query)
- **HTTP客户端**: Axios
- **表单处理**: React Hook Form

### 3.2 后端技术栈

- **编程语言**: Go
- **Web 框架**: Gin
- **ORM 框架**: GORM
- **数据库**: MySQL/PostgreSQL/SQLite
- **配置管理**: Viper
- **命令行接口**: Cobra
- **身份验证**: JWT
- **日志系统**: 自定义日志系统（基于 lumberjack）

### 3.3 数据存储

- **主数据库**: MySQL/PostgreSQL/SQLite
- **缓存**: Redis (未来扩展)
- **文件存储**: 本地存储/云存储 (未来扩展)

## 4. 系统模块

### 4.1 用户认证模块

负责用户注册、登录、权限验证等功能。

**主要功能**:
- 用户注册和登录
- JWT令牌管理
- 权限验证
- 用户信息管理

### 4.2 作品管理模块

负责作品的创建、编辑、删除和查询等功能。

**主要功能**:
- 作品创建和编辑
- 作品分类和标签
- 作品状态管理
- 作品搜索和筛选

### 4.3 章节管理模块

负责章节的创建、编辑、删除和查询等功能。

**主要功能**:
- 章节创建和编辑
- 章节排序和组织
- 章节发布和草稿管理
- 章节内容版本控制

### 4.4 角色管理模块

负责角色的创建、编辑、删除和查询等功能。

**主要功能**:
- 角色创建和编辑
- 角色属性管理
- 角色与作品关联
- 角色成长履历管理

### 4.5 世界观管理模块

负责世界观的创建、编辑、删除和查询等功能。

**主要功能**:
- 世界观分类管理
- 世界观条目创建和编辑
- 世界观与作品关联
- 世界观条目关系管理

## 5. 数据流设计

### 5.1 用户请求处理流程

```
用户请求 → Next.js前端 → API代理 → Gin后端 → 数据库 → Gin后端 → API代理 → Next.js前端 → 用户响应
```

### 5.2 数据同步流程

```
前端状态变更 → API调用 → 后端处理 → 数据库更新 → 响应返回 → 前端状态更新 → UI刷新
```

## 6. 安全设计

### 6.1 身份验证

- 使用 JWT 进行身份验证
- 密码使用 bcrypt 进行哈希存储
- 支持 HTTPS 加密传输

### 6.2 权限控制

- 使用中间件进行权限验证
- 实现基于角色的访问控制
- 防止越权访问

### 6.3 数据安全

- 敏感信息加密存储
- SQL 注入防护
- XSS 防护
- CSRF 防护

## 7. 性能优化

### 7.1 前端优化

- 使用 Next.js 自动代码分割
- 实现服务端渲染和静态生成
- 使用 React Query 进行数据缓存
- 图片优化和懒加载

### 7.2 后端优化

- 使用数据库索引提高查询性能
- 实现分页查询避免大数据量传输
- 使用连接池减少连接开销
- 实现缓存机制

### 7.3 网络优化

- 使用 CDN 加速静态资源
- 实现 HTTP/2 支持
- 压缩响应数据
- 实现缓存策略

## 8. 部署架构

### 8.1 开发环境

- 前端: Next.js 开发服务器
- 后端: Gin 开发服务器
- 数据库: SQLite
- 部署: Docker Compose

### 8.2 生产环境

- 前端: Next.js 应用服务器
- 后端: Gin 应用服务器
- 数据库: MySQL/PostgreSQL
- 负载均衡: Nginx
- 部署: Kubernetes/Docker Swarm

## 9. 监控和日志

### 9.1 监控

- 实现健康检查接口
- 集成 Prometheus 监控
- 使用 Grafana 进行可视化
- 实现应用性能监控 (APM)

### 9.2 日志

- 实现统一日志格式
- 使用 ELK 进行日志分析
- 实现日志轮转和归档
- 支持日志级别控制

## 10. 扩展性设计

### 10.1 水平扩展

- 支持应用服务器水平扩展
- 实现数据库读写分离
- 使用消息队列处理异步任务
- 实现微服务架构 (未来扩展)

### 10.2 功能扩展

- 模块化设计便于功能扩展
- 使用插件机制支持第三方集成
- 实现 API 版本控制
- 支持多语言和国际化
