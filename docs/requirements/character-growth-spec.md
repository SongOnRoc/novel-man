# **需求文档: 角色关系与成长管理界面**

**版本:** 1.0
**日期:** 2025-07-27
**负责人:** `doc-writer`

---

## **1. 概述**

### **1.1. 背景**

随着后端架构升级，我们引入了 `WorkCharacter` 和 `EntityRelationship` 模型，使得记录和管理角色在特定作品中的成长轨迹与关系网络成为可能。本文档旨在详细描述一个全新的前端功能界面，以充分利用这些新能力，为创作者提供更强大的角色管理工具。

### **1.2. 目标**

*   为单个作品提供一个集中的角色管理中心。
*   清晰、直观地展示角色的成长履历。
*   可视化地呈现角色之间的关系网络。
*   提供便捷的编辑功能，允许用户手动维护角色的成长和关系数据。
*   为未来集成AI辅助功能奠定基础。

---

## **2. 功能详述**

### **2.1. 入口**

*   **位置:** 在单个作品的管理页面中，应存在一个名为“角色管理”或类似名称的导航标签/按钮。
*   **URL (建议):** `/works/[id]/characters`
    *   **注:** 此处使用 `[id]` 与现有作品相关路由 (`/works/[id]`) 的参数保持一致，以避免后端路由冲突。
*   **行为:** 点击该入口后，用户将进入“角色关系与成长管理”的主界面。

### **2.2. 主界面布局**

界面采用双栏布局，以提供清晰的信息结构和流畅的用户体验。

*   **左侧栏 (角色列表):**
    *   **内容:** 垂直显示已关联到当前作品的所有角色的列表。
    *   **列表项:** 每个列表项应至少显示角色的头像 (`avatar_url`) 和姓名 (`name`)。
    *   **交互:**
        *   点击列表中的某个角色，右侧主区域将加载并显示该角色的详细信息。
        *   应有一个“添加角色到作品”的按钮，允许用户从全局角色库中选择一个或多个角色关联到当前作品。
        *   当前选中的角色应有高亮显示。

*   **右侧主区域 (角色详情):**
    *   **内容:** 显示当前在左侧栏选中的角色的详细信息。
    *   **默认视图:** 默认情况下，显示角色的基本信息和一个或多个功能模块（如“成长履历”和“关系网络”）。
    *   **空状态:** 如果左侧没有选中任何角色，右侧区域应显示一个提示，引导用户“请从左侧选择一个角色以查看详情”。

### **2.3. 右侧主区域功能**

#### **2.3.1. 成长履历 (Growth Log)**

该模块是本功能的核心，用于记录和展示角色的成长过程。

*   **显示形式:**
    *   建议采用**时间线 (Timeline)** 的形式进行展示。时间线上的每个节点代表一条成长记录。
    *   每条记录应清晰地展示以下信息：
        *   **关联章节:** 如果该成长事件与某个具体章节相关联，应显示章节标题，并提供链接跳转到该章节的编辑页面。
        *   **事件摘要:** 对引发角色成长的关键事件的简短描述。
        *   **人物成长:** 具体描述角色在该事件中获得了哪些变化或成长（例如，技能提升、心态转变、获得新物品等）。

*   **交互功能:**
    *   **添加记录:**
        *   在模块顶部应有一个“添加成长记录”的按钮。
        *   点击后，弹出一个表单或行内编辑器，包含以下字段：
            *   `关联章节` (可选, 下拉选择框，数据源为当前作品的章节列表)
            *   `事件摘要` (必填, 文本输入框)
            *   `人物成长` (必填, 文本区域)
    *   **编辑记录:**
        *   每条成长记录旁边应有“编辑”按钮。
        *   点击后，允许用户在与添加功能相同的表单/编辑器中修改该条记录的内容。
    *   **删除记录:**
        *   每条成长记录旁边应有“删除”按钮。
        *   点击后，弹出确认对话框，防止误操作。确认后，该条记录被移除。
    *   **AI 总结 (未来功能):**
        *   在模块顶部应有一个“AI总结”按钮，目前可以置灰或隐藏。
        *   **用户故事:** “作为一名创作者，我希望能一键分析指定章节的内容，让AI自动为我提炼出角色的成长事件并生成履历条目，以节省我的时间。”
        *   **预期行为 (未来):** 点击后，允许用户选择一个或多个章节，然后调用后端AI服务进行分析，并将生成的成长记录草稿添加到时间线中，供用户确认和修改。

#### **2.3.2. 关系网络 (Relationship Network)**

该模块用于可视化和管理与当前选中角色相关的所有关系。

*   **显示形式:**
    *   **可视化关系图:**
        *   强烈建议使用图表库（如 `react-flow` 或 `d3.js`）来渲染一个关系网络图。
        *   图的中心节点是当前选中的角色。
        *   周围的节点代表与该角色有关系的其他实体（其他角色、世界观条目等）。
        *   节点之间用带标签的边连接，标签上显示 `RelationshipType` (关系类型)。
        *   鼠标悬停在边或节点上时，可以显示一个浮动卡片，展示关系的详细 `Description` 或实体的简要信息。
    *   **备选方案 (卡片列表):** 如果可视化实现复杂，可降级为卡片列表。每个卡片代表一条关系，显示目标实体、关系类型和描述。

*   **交互功能:**
    *   **添加关系:**
        *   在模块顶部应有一个“添加关系”的按钮。
        *   点击后，弹出一个表单，包含以下字段：
            *   `目标实体` (必填, 一个支持搜索和分类选择的查找组件，允许用户从所有角色和世界观条目中选择一个实体)
            *   `关系类型` (必填, 文本输入框，建议提供预设选项如“朋友”、“家人”、“敌人”、“盟友”等)
            *   `关系描述` (可选, 文本区域)
    *   **编辑关系:**
        *   在关系图的边或关系卡片上，应有“编辑”按钮。
        *   点击后，允许用户在与添加功能相同的表单中修改关系类型和描述。目标实体不可修改。
    *   **删除关系:**
        *   在关系图的边或关系卡片上，应有“删除”按钮。
        *   点击后，弹出确认对话框。确认后，该条关系被移除。

## **3. 数据模型参考**

### **3.1. `WorkCharacter`**

```go
// 来自 backend/internal/models/models.go
type WorkCharacter struct {
    WorkID      int64 `gorm:"primaryKey" json:"work_id"`
    CharacterID uint  `gorm:"primaryKey" json:"character_id"`
    BaseInfo
    WorkSpecificAlias  *string        `json:"work_specific_alias,omitempty"`
    WorkSpecificStatus *string        `json:"work_specific_status,omitempty"`
    GrowthLog          datatypes.JSON `json:"growth_log"`
}
```

### **3.2. `EntityRelationship`**

```go
// 来自 backend/internal/models/models.go
type EntityRelationship struct {
    ID uint `gorm:"primarykey" json:"id"`
    BaseInfo
    SourceEntityType string `gorm:"size:100;not null" json:"source_entity_type"` // e.g., "character"
    SourceEntityID   uint   `gorm:"not null" json:"source_entity_id"`
    TargetEntityType string `gorm:"size:100;not null" json:"target_entity_type"` // e.g., "character", "worldview_item"
    TargetEntityID   uint   `gorm:"not null" json:"target_entity_id"`
    RelationshipType string `gorm:"size:100;not null" json:"relationship_type"` // e.g., "ally", "enemy"
    Description      string `gorm:"type:text" json:"description"`
}
```

### **3.3. `GrowthLog` JSON 结构 (建议)**

为了确保“成长履历”功能的数据一致性，建议 `GrowthLog` 字段存储一个JSON数组，其中每个对象遵循以下结构：

```json
[
  {
    "log_id": "unique_identifier_string", // 用于React key和可能的数据库操作
    "chapter_id": "chapter_uuid_or_id", // 可选，关联的章节ID
    "event_summary": "角色在黑森林中首次遭遇狼群。", // 必填，事件摘要
    "growth_description": "学会了基础的剑术防御，克服了对黑暗的恐惧。", // 必填，成长描述
    "timestamp": "YYYY-MM-DDTHH:MM:SSZ" // 记录创建或事件发生的时间戳
  }
]
```

## **4. 非功能性需求**

*   **性能:** 关系网络图在角色关系数量超过50个时应保持流畅加载和交互。
*   **易用性:** 所有交互应直观，无需用户阅读长篇说明即可上手。
*   **扩展性:** 界面设计应考虑未来可能增加的新实体类型和关系属性。
