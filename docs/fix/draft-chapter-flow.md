# 草稿与章节 · 创建流程与信息架构契约

> 本文档固化「草稿 / 章节」的创建流程、入口设计与业务铁律。
> 背景：作品内的草稿/章节入口曾经多而混乱、文案与行为不符、概念反复横跳。
> 经讨论定稿后形成本契约，**后续所有相关实现以此为准，避免再次回到混乱逻辑**。
>
> 定稿日期：2026-06-15

---

## 一、核心数据模型

| 概念 | 定义 | 归属 |
|---|---|---|
| **草稿（Draft）** | 创作的中间态、可自由编辑保存 | 作品草稿（有 `workId`）/ 全局草稿（无 `workId`，即"灵感片段"） |
| **章节（Chapter）** | 正式内容 | 始终归属某作品 |

### 业务铁律（最重要，不可破坏）

> **章节只能由草稿「发布」而来，不允许单独新建空白章节。**

- 章节的唯一来源是「草稿发布」（唯一例外见第四节·批量导入，且该例外也走草稿态）。
- 这条铁律保证章节来源单一，后续「章节↔草稿联动」「智能提取」等功能无需处理多来源特例。

### 三个核心动作

1. **新建** = 永远是新建**草稿**（不存在"新建空白章节"）
2. **发布** = 草稿 → 章节
3. **引入** = 全局草稿 → 关联到作品（设 `workId`）→ 成为作品草稿

---

## 二、章节的完整创建过程

```
新建（任意"新建"入口）
   → 打开草稿页（/works/[id]/drafts/new）
   → 写作，自动保存为草稿
   → 用户主动「发布」
   → 草稿成为章节
   → 章节可编辑 / 修改 / 删除
```

**要点**：
- 所有"新建"按钮（无论在草稿语境还是章节语境）点击后**都打开草稿页**。
- "新建章节 / 直接建空白章节"的概念**不存在**，相关误导文案全部废弃。

## 三、新建按钮统一规则

- 所有"新建"入口都指向 `/works/[id]/drafts/new`（作品草稿）。
- **文案按语境**（见 `ui-design-language.md`·操作文案规范）：草稿/章节语境内用「新建」（2 字，不重复上下文）；中性位置（作品 hero）用「新建草稿」明确对象。
- **章节语境（章节 tab / 章节列表页）的「新建」需加引导提示**：
  - 提示（示意）：「章节由草稿发布而来，这里将先创建草稿，写完后发布为章节。」
  - **可关闭**：「不再提示」用 `localStorage` 记住。草稿语境的「新建」不需要提示。

## 四、批量导入（采用方案 A）

> **批量导入 = 导入为草稿 + 批量发布为章节**（不做"直接导入为章节"的特例）。

- 导入内容先全部落为**作品草稿**，保持"章节=草稿发布产物"的铁律不破。
- 提供**批量发布**能力：导入后的草稿可「全选 → 一键批量发布」为章节。
- 好处：模型统一无后门；导入后用户有"检查 / 调整再发布"的缓冲。
- 代价（可接受）：比"直接导入为章节"多一步批量发布。

**现状问题（2026-06-17 核查）→ 已整改（2026-06-20）**：
- 章节列表页原"导入章节"功能（`ImportDialog` + `useImportChapters` + `POST /chapters/import`）**直接导入为章节**，违反铁律（后门）。
- 已按方案 A 整改：章节页入口改为"导入为草稿"，前端不再暴露任何"直接导入为章节"的能力。

**实现进度（2026-06-20 完成）**：
- [x] 后端 `POST /drafts/import?work_id=X`（复用 `upload.GenericImporter[models.Draft]` 批量导入为作品草稿；校验作品归属；不生成章节）
- [x] 后端 `POST /drafts/batch-publish`（接收 `{ draft_ids: []uint }`，逐篇复用 `Publish()`，部分成功语义返回 `ImportResult`）
- [x] 前端 `useImportDrafts` hook（`importDraftsService` → `/drafts/import`）
- [x] 前端 `useBatchPublishDrafts` hook（`batchPublishDraftsService` → `/drafts/batch-publish`）
- [x] 章节列表页"导入章节" → 改为"导入为草稿"（调 `useImportDrafts`，导入后跳作品草稿列表 + toast 引导批量发布）
- [x] 草稿列表页"批量发布"入口（`BatchPublishDraftsDialog`：勾选多篇 → 调 `useBatchPublishDrafts`）
- [x] `useImportChapters` / `importChaptersService` 标记 `@deprecated`（UI 已不再调用；`POST /chapters/import` 后端路由暂保留兼容）

> 备注：后端导入器（`GenericImporter[T]` 泛型 + 解析/创建解耦）与单篇 `Publish()` 早已现成，方案 A 实际只补了两层薄包装（importer wrapper + handler/route）。

## 五、全局草稿箱入口（升级为"引入灵感"）

- **侧边栏**保留全局草稿箱独立入口（管理所有未关联灵感草稿），不变。
- **作品内**：把原来"打开/查看全局草稿箱"（只是跳 `/drafts`，纳入流程断裂）**升级为"从灵感箱引入"**：
  ```
  作品草稿列表页 [从灵感箱引入]
     → 弹出「未关联作品的全局草稿」列表
     → 勾选一篇 / 多篇
     → 关联到当前作品（updateDraft 设 workId）
     → 立即出现在作品草稿列表，后续可正常发布为章节
  ```
- 意图聚焦："把这条灵感纳入这部作品"，一步到位，而非"跳去全局箱自己找路"。
- **移除**作品内其它分散的"全局草稿箱"跳转（草稿 tab、空态、草稿列表页 header 的"查看未关联草稿箱"等）。

## 六、整体入口设计（目标态）

| 位置 | 入口设计 |
|---|---|
| **作品 hero**（WorkOverviewHeader） | `[新建草稿]`（→drafts/new） `[编辑作品]`；**去掉"新建章节"** |
| **管理页·草稿 tab** | 最近 N 篇草稿（概览）+ `[查看全部草稿→/works/[id]/drafts]` `[+ 新建草稿→drafts/new]`；**去掉全局草稿箱入口** |
| **管理页·章节 tab** | 最近 N 章（概览）+ `[查看全部章节→/works/[id]/chapters]` `[+ 新建（带提示）→drafts/new]`；**去掉"从草稿发布章节"跳列表** |
| **管理页·大纲/角色/设定 tab** | 保持"进入模块卡"，后续单独优化 |
| **作品草稿列表页**（/works/[id]/drafts） | 完整列表 + 搜索 + 分页 + `[新建草稿]` + `[从灵感箱引入]`（替换原"查看未关联草稿箱"） |
| **章节列表页**（/works/[id]/chapters） | 完整章节列表 + `[新建（带提示）→drafts/new]` + **批量导入入口**（方案 A） |
| **全局草稿箱**（/drafts，侧边栏） | 全局灵感草稿管理；弹窗新建可选「关联作品」；关联了作品→跳作品草稿编辑页，未关联→全局草稿编辑页 |

### tab = 概览，列表页 = 全量

- **作品管理页的各 tab**：只展示「最近 N 条」+「查看全部」+「新建」，定位是概览。
- **专门列表页**：承载完整列表、搜索、分页、批量操作、各项管理。
