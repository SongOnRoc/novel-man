# Task: frontend-local-build

# Type: fix

# 开始日期: 2026-03-30

## 背景

当前本地执行 `frontend` 的 `pnpm build` 失败，用户观察到项目对 `127.0.0.1` / `localhost` 有限制，怀疑环境变量使用方式影响了本地编译。

初步排查发现，当前构建在进入业务代码环境校验前，先因为 `frontend/node_modules/next/dist/bin/next` 缺失而失败，因此需要先恢复本地构建链，再继续确认是否存在 `NEXTAUTH_URL` 校验导致的二次阻塞。

## 目标

- 找出当前本地无法编译的第一根因
- 用最小改动恢复本地 `pnpm build` 路径
- 若依赖修复后仍存在 `NEXTAUTH_URL` / `localhost` 校验阻塞，继续定位并处理

## 范围

- 包含 `frontend` 本地依赖完整性检查
- 包含与本地构建直接相关的环境变量校验逻辑排查
- 不包含与本次构建失败无关的章节系统功能改造
- 不包含线上部署配置调整

## 验收标准

- 能在当前工作区重新执行 `frontend` 的 `pnpm build`
- 若构建仍失败，能够给出明确的下一层根因与证据
- 不削弱线上环境对非法 `NEXTAUTH_URL` 的保护

## 约束与风险

- 当前工作区存在大量未提交改动，不能破坏用户现有修改
- 依赖重装可能改动 `node_modules` 状态，但不应擅自修改业务代码以掩盖问题
- 若构建失败根因转移到环境变量逻辑，需要区分“本地 build 验证”与“线上生产运行”语义

## 初步计划

1. 确认 `frontend` 当前依赖安装是否完整
2. 修复依赖缺失并重新执行 `pnpm build`
3. 若进入 `NEXTAUTH_URL` / `localhost` 校验失败，再做最小代码修复
4. 记录验证结果与后续建议
