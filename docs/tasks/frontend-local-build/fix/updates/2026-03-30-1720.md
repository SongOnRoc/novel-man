# 本次做了什么

- 为 `NEXTAUTH_URL` 的生产校验补充了“严格生产运行阶段”判断，不再仅依赖 `NODE_ENV === "production"`。
- 新增 `frontend/src/lib/runtime-env.ts`，统一判断当前是否处于需要执行严格公网 Origin 校验的运行阶段。
- 将 `frontend/src/lib/fetch.ts` 与 `frontend/src/lib/auth.ts` 中的生产校验统一改为基于该判断执行。
- 重新执行本地 `pnpm build`，确认本地构建不再被 `localhost/127.0.0.1` 限制误伤。

# 为什么这么做

- 当前项目原有逻辑把“生产环境运行安全校验”和“本地 production build”混为一谈，导致一旦构建阶段命中相关逻辑，就会因 `NEXTAUTH_URL=http://localhost:3000` 直接失败。
- 本次改动的目标是保留线上运行时的严格限制，同时避免本地构建验证场景被误伤。

# 影响范围

- 新增：`frontend/src/lib/runtime-env.ts:1`
- 修改：`frontend/src/lib/fetch.ts:1`
- 修改：`frontend/src/lib/auth.ts:1`

# 验证方式与结果

- 执行 `pnpm build`
  - 首次验证时出现新的依赖层错误：`next/dist/client/components/builtin/global-not-found` 缺失
  - 继续执行 `pnpm install --force --prefer-offline=false` 修复 `next` 包内部文件缺失
- 再次执行 `pnpm build`
  - 结果：通过
- 结论：
  - 本地 `build` 已不再被 `localhost/127` 校验误伤
  - 当前线上运行安全限制仍保留在 `strict production runtime` 下

# 后续待办

- 若需要进一步提高可维护性，可补针对 `runtime-env` 的单元测试，明确 `build` 阶段与线上运行阶段的行为边界。
- 若再次出现 `next` 包内部文件缺失，需进一步调查本机 pnpm store 或依赖缓存稳定性。
