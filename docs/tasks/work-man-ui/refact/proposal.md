# 背景

当前分支围绕作品工作台前端进行持续重构，涉及全局草稿箱、作品草稿发布、章节管理页、章节号调整等一组相关改动。由于改动横跨多个页面和组件，且已有较多未提交变更，需要将本次针对前端 diff 的审查结论沉淀到任务文档，避免问题只停留在会话上下文中。

# 目标

- 对当前前端改动做一次面向提交前的代码审查。
- 识别阻塞问题、非阻塞改进项、测试缺口与风险点。
- 将本次 review 结论落盘，便于后续修复和复核。

# 范围

- 审查草稿发布流程相关页面与组件。
- 审查章节列表、章节号调整相关页面与工具函数。
- 审查本次 diff 新增或修改的相关测试。

不做什么：

- 不直接修改业务代码。
- 不运行测试或构建命令得出通过性结论。
- 不处理后端配置与非前端功能实现。

# 验收标准

- 已产出一份可执行的前端代码审查报告。
- 报告中明确列出阻塞问题、建议改进、补测项和风险等级。
- 本次会话的关键结论已写入 `review/` 与 `updates/`。

# 约束与风险

- 当前工作区存在较多未提交改动，审查需只针对本次前端影响面下结论。
- 不允许回退用户已有修改。
- 草稿发布与章节重排流程存在状态同步和部分成功风险，属于本次重点关注对象。

# 初步计划

- 读取 git 状态与前端相关 diff，确认审查范围。
- 阅读关键页面、组件、工具函数与测试文件。
- 归纳阻塞问题、非阻塞建议与测试缺口。
- 将结论写入任务文档并反馈给用户。
