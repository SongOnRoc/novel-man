# 背景

当前任务继续推进作品管理前端优化，依据 `docs/req/webui/页面优化.md`，从作品章节相关页面开始逐页收口。当前目标页为 `http://localhost:3000/works/47/chapters/50`，即单章节阅读工作区。

现状中该页虽然已经具备阅读、分析、导出、片段提取等能力，但页面层级与信息占比仍不合理：头部信息密度偏低、正文与操作区割裂、分析区是后置附加块，缺少更现代、紧凑、连续的工作区体验。

# 目标

- 结合项目现有作品工作台视觉语言，为章节详情页输出一版新的 UI/UX 设计方案。
- 保持现有大框架不变，优化信息结构、视觉层次与操作路径。
- 先通过 Pencil 产出设计稿，为后续前端实现提供清晰依据。

# 范围

- 分析章节详情页当前实现：`frontend/src/app/(main)/works/[id]/chapters/[chapterId]/page.tsx`
- 参考作品工作台与相邻页面的已有视觉语言与组件模式。
- 产出章节详情页桌面优先设计稿，并兼顾移动端布局思路。

不做什么：

- 本轮先不直接改前端实现代码。
- 不重做全站设计系统，只在现有风格内优化该页面。
- 不改变核心功能集合和主要路由结构。

# 验收标准

- 已形成一份可复用的章节详情页优化设计结论。
- 已在 Pencil 中画出设计稿，并完成基础视觉核对。
- 本次会话的 proposal、plan/design、updates 已写入 `docs/tasks/work-man-ui/refact/`。

# 约束与风险

- 必须延续项目当前“卡片化 + 柔和高亮 + 工作台”视觉语言，不能脱离现有产品气质。
- 页面仍需承载阅读、导出、分析、片段提取等现有能力，避免设计只重展示不重操作。
- 当前环境可能未打开现成 Pencil 文档，需要新建设计画布承载本次方案。

# 初步计划

- 阅读目标页及作品工作台关键页面，提炼统一的 UI 模式。
- 明确当前章节页的结构问题与重设计方向，并落盘。
- 在 Pencil 中绘制章节详情页高保真设计稿。
- 导出并检查设计稿，整理为后续实现输入。
