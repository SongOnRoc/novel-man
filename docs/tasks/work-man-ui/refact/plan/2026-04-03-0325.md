# 作品管理页优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变 `/works/:id` 大框架的前提下，优化桌面端信息密度，并为移动端补齐 sticky 动作条、更多 Bottom Sheet 和 Header 折叠所需的页面结构。

**Architecture:** 以 `frontend/src/app/(main)/works/[id]/page.tsx` 为主修改点，优先做最小范围重构：把当前大卡拆成更紧凑的 header 结构，抽出移动端 sticky actions / more sheet 子组件与小型 hook，避免把页面继续堆大。继续使用现有 shadcn/radix `Sheet` 与按钮体系，减少新依赖与视觉分叉。

**Tech Stack:** Next.js App Router, React, TypeScript, shadcn/ui, Radix Sheet, Vitest, Testing Library

### Task 2: 抽出作品页顶部与移动端动作组件

**Files:**
- Create: `frontend/src/features/works/components/WorkOverviewHeader.tsx`
- Create: `frontend/src/features/works/components/WorkMobileStickyActions.tsx`
- Create: `frontend/src/features/works/components/useWorkHeaderCollapse.ts`
- Modify: `frontend/src/app/(main)/works/[id]/page.tsx`

- [ ] **Step 1: 新建 `WorkOverviewHeader.tsx`**

实现职责：

- 接收作品标题、状态、更新时间、统计数据、简介、封面占位。
- 桌面端输出：左侧较窄封面区 + 右侧标题/Meta/Stats/主动作。
- 移动端输出：压缩后的标题/Meta/Stats，保留封面弱占位，不把首屏让给低价值容器。

- [ ] **Step 2: 新建 `WorkMobileStickyActions.tsx`**

实现职责：

- 仅在移动端显示 sticky actions。
- 左侧轻量按钮：`新建草稿`
- 右侧按钮：`更多操作`
- 点击 `更多操作` 后打开 bottom sheet。

- [ ] **Step 3: 新建 `useWorkHeaderCollapse.ts`**

实现职责：

- 基于滚动容器或 `window` scroll 记录 `isCollapsed`。
- 初始仅返回布尔值，不做复杂动画。
- 用于页面后续把 header 从展开态切到紧凑态。

- [ ] **Step 4: 在 `page.tsx` 中接入新组件，移除旧的“大卡式”结构**

重构目标：

- 删除当前 `基础信息 / 统计信息 / 关键操作` 三段大卡堆叠结构。
- 用单一 header 区替代。
- 将桌面端主动作顺序调整为：`新建草稿`、`新建章节`、`编辑作品`。
