# Code Review Report

## 1) 变更摘要

- 本次前端改动主要集中在草稿发布链路和作品章节管理链路。
- 全局草稿箱 `frontend/src/app/(main)/drafts/page.tsx` 新增了“选择作品 -> 规范化章节标题 -> 发布为章节”的两步弹窗流程。
- 草稿编辑页 `frontend/src/app/(main)/drafts/[id]/edit/page.tsx` 也接入了同样的发布流程。
- 章节页 `frontend/src/app/(main)/works/[id]/chapters/page.tsx` 新增了正序/倒序、客户端分页，以及“调整章节号”能力。
- 新增了章节编号与重排工具：`frontend/src/features/chapters/lib/chapterNumbering.ts`、`frontend/src/features/chapters/lib/chapterReorder.ts`。
- 相关测试主要补在 `frontend/src/app/(main)/works/[id]/chapters/page.test.tsx` 和 `frontend/src/app/(main)/drafts/page.test.tsx`，但对新发布流程覆盖还不够。

## 2) 风险评估（结论先行）

- 风险等级：中-高。
- 主要风险不在 UI 外观，而在“状态残留导致发到错误作品”和“章节重排中途失败导致服务端顺序部分更新”这两类行为问题。
- 如果这些问题上线，用户最容易遇到的是：发布到错误作品、章节号重复或错乱、以及在大数据量下章节页变慢。

Top 风险点：

1. 草稿发布弹窗的作品选择状态残留。
2. 非受控 `Select` 导致展示值与提交值不同步。
3. 章节重排按条更新，缺少原子性保障。
4. 章节页通过 `limit: 9999` 拉全量数据并在前端分页。

## 3) 阻塞问题（必须修）

### 3.1 全局草稿箱发布流程存在作品选择残留

- 位置：`frontend/src/app/(main)/drafts/page.tsx:316`、`frontend/src/app/(main)/drafts/page.tsx:455`
- 问题：发布草稿时 `selectedWorkId` 只在 `draft.workId` 存在时赋值，没有在未关联草稿场景显式清空；同时作品选择器使用 `defaultValue`，不是受控 `value`。
- 影响：如果用户先发布过一个已关联作品的草稿，再发布另一个未关联草稿，弹窗可能沿用上次作品选择，导致草稿被误发到错误作品。
- 建议修复：在 `handlePublish` 中对无 `workId` 的草稿执行 `setSelectedWorkId(undefined)`；将 `Select` 改为受控模式，并在关闭弹窗时统一重置相关状态。

### 3.2 草稿编辑页的作品选择器存在相同的受控问题

- 位置：`frontend/src/app/(main)/drafts/[id]/edit/page.tsx:195`
- 问题：编辑页发布流程里的 `Select` 同样使用 `defaultValue={selectedWorkId}`，属于非受控组件。
- 影响：当草稿数据异步更新或弹窗生命周期内 state 变化时，UI 展示的选中项可能与实际提交的 `selectedWorkId` 不一致，增加误发布风险。
- 建议修复：改为 `value={selectedWorkId}` 的受控写法，并在弹窗打开时显式初始化、关闭时显式重置。

### 3.3 章节重排存在部分成功风险

- 位置：`frontend/src/app/(main)/works/[id]/chapters/page.tsx:214`
- 问题：章节重排通过前端循环调用 `updateChapterAsync` 逐条提交多个更新，没有事务或批量接口保证一致性。
- 影响：一旦中途某条更新失败，服务端会留下“部分章节已更新、部分未更新”的中间状态，可能导致 `displayOrder` 重复、标题前缀错乱、顺序异常；当前仅 `router.refresh()`，无法回滚已成功的更新。
- 建议修复：优先提供后端批量 reorder 接口并保证原子性；如果短期无法提供，至少补充可回滚或补偿机制，并在界面上限制该操作的失败窗口。

## 4) 建议改进（非阻塞）

### 4.1 章节页当前采用全量拉取再前端排序/分页

- 位置：`frontend/src/app/(main)/works/[id]/chapters/page.tsx:97`
- 建议：避免 `limit: 9999` 的全量请求，优先让服务端支持按 `displayOrder` 排序和分页；若短期仍用前端分页，需要处理 `page > totalPages` 的回退逻辑。

### 4.2 删除或重排后当前页可能落在空页

- 位置：`frontend/src/app/(main)/works/[id]/chapters/page.tsx:120`
- 建议：在章节数据变化后，如果当前 `page` 超出最大页码，应自动修正 query param，避免用户停留在空白页。
