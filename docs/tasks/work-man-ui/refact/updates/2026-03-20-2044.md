# 本次做了什么

- 在更深的 UI 结构性评估基础上，进一步提炼出一份“UI 模式取舍清单”。
- 将当前前端中必须停止复用的模式和可以保留复用的模式分开整理。
- 这份清单的目的，是为后续章节系统设计建立约束，避免继续沿用展示型工作台思路。

# 为什么这么做

- 仅仅指出“哪些页面有问题”还不够，后续设计真正需要的是一套明确的取舍标准。
- 没有这份清单，章节系统很容易再次回到“大卡片 + 模块说明 + 多按钮 + 列表”的旧路径上。

- 验证方式：在前两轮页面阅读和评估结论的基础上，抽象跨页面的重复问题模式和可复用模式。
