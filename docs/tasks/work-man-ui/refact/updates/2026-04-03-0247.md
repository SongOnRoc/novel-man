# 本次做了什么

- 针对 `/works/:id`（示例 `/works/47`）页面的信息密度与移动端体验问题，完成了可视化线框迭代与“更多”交互方案收敛。
- 使用 pencil 产出并稳定了 4 张关键状态示意图（桌面端、移动端默认态、移动端更多打开态、移动端折叠态）。
- 清理了中间产出的冗余设计资产（例如 Popover 探索稿与残留导出），避免后续讨论混乱。

# 为什么这么做

- 现状痛点：页面存在“一个信息点占一个大卡”的信息密度失衡问题，移动端首屏被低价值容器挤占，管理区（Tabs）进入成本高。
- 约束：
  - 不改变大布局框架（上半作品信息 + 下半内容管理 Tabs）。
  - 桌面端与移动端尽量保持一致体验，不做两套产品逻辑。
  - 操作逻辑优先级：移动端默认开始写作应为“新建草稿（绑定作品）”，草稿完成后再发布为章节。
- 因为上述约束会直接影响布局、按钮优先级、滚动模型与“更多”承载方式，所以先通过线框把交互与比例定下来再进入实现。

# 结论与当前定稿

## 1. 桌面端（已基本认可）

- 封面缩小为左侧窄列，右侧集中展示：标题 + Meta/Stats（压缩成行展示）+ 主操作按钮。
- 目的：减少卡片数量与留白，让首屏信息密度更合理。

对应线框：`docs/tasks/work-man-ui/refact/design/XOEEA.png`

## 2. 移动端默认态（More Closed）

- 顶部信息区压缩，优先让 Tabs 管理区进入视野。
- 底部保留 sticky 动作条：
  - `新建草稿` 作为默认写作入口，但按钮形态轻量化（避免占满空间）。
  - `更多` 固定在右侧（不让左侧按钮占满剩余空间）。

对应线框：`docs/tasks/work-man-ui/refact/design/dBpvw.png`

## 3. 移动端“更多”打开态（Bottom Sheet）

- 采用贴底铺满宽度的 Bottom Sheet（从底部贴边升起，不留底部空隙）。
- 内容策略：当前仅两项动作，使用“一行两列等宽均分”，不展示冗余解释文案。
- 关闭方式：右上角 `X`（同时允许点遮罩关闭）；移除了底部大“关闭”按钮并压缩抽屉高度。
- “更多”菜单项当前与客户端保持一致：`新建章节`、`编辑作品`。

对应线框：`docs/tasks/work-man-ui/refact/design/G5YEB.png`

## 4. 移动端折叠态（Header Collapsed）

- 折叠只收缩顶部 Header 信息区，不移动底部 sticky 动作入口（避免入口位置跳变造成割裂）。
- 折叠态作为必须关注状态保留。

对应线框：`docs/tasks/work-man-ui/refact/design/OttOH.png`
