## 为什么这么做

- 当前计划虽然只要求“最小异步分析流程”，但仓库已存在统一 AI 服务层，继续把逻辑写死在组件侧会放大后续接真实接口的改造成本。
- 先把章节分析收口到独立 service，可以让阅读页和编辑页继续保持现状，同时把“AI 请求边界”从 UI 中剥离出去。
- 保留本地回退逻辑可以避免因为 AI 服务不可用而导致分析功能完全失效，适合当前仍在重构期的章节工作区。
