## 本次做了什么

- 将章节分析从同步直出结果调整为统一的异步状态流，新增 `idle / loading / success / error` 四种状态。
- 新增 `useChapterAnalysis`，统一阅读态与编辑态的分析打开、切换类型、失败重试与关闭行为。
- 为桌面端 `ChapterAnalysisPanel` 与移动端 `ChapterAnalysisSheet` 增加加载态、错误态和重试按钮展示。
- 更新阅读态与编辑态测试，覆盖异步加载、切换分析类型、错误重试和移动端 sheet 展示。

## 为什么这么做

- 当前计划明确推荐将章节分析从“本地同步生成结果”推进到“更真实的异步分析流”。
- 把状态管理抽到 hook 后，阅读页与编辑页可以共享同一套交互语义，减少后续接入真实异步接口时的重复改造。
- 先补齐加载、失败和重试语义，可以让章节工作区更接近真实产品行为，而不只是交互骨架。
