## 本次做了什么

- 在 `frontend` 下执行了整体 `pnpm build`，确认当前首个构建阻塞发生在 `/api/auth/[...nextauth]` 的页面数据收集阶段。
- 追踪到根因不是章节功能逻辑，而是 `frontend/src/lib/fetch.ts` 在模块加载时立即计算服务端 `baseURL`，从而过早触发了生产模式下的 `NEXTAUTH_URL` 安全校验。
- 将 `frontend/src/lib/fetch.ts` 中的 `baseURL` 改为通过 `getBaseURL()` 按需计算，把安全校验从模块初始化延后到真正发请求时。
- 重新执行 `pnpm build`，确认整个前端构建已经通过。

## 为什么这么做

- 当前报错信息显示生产构建阶段拒绝 `NEXTAUTH_URL=http://localhost:3000`，但构建时并没有真正发起需要该地址的服务端请求。
- 问题的根源是“校验时机过早”，不是“校验规则本身错误”。
- 将校验延迟到真实请求发生时，可以保留生产运行时的安全边界，同时避免无关模块 import 在 build 阶段误伤。

## 影响范围

- `frontend/src/lib/fetch.ts:1`

## 验证方式与结果

- 已执行：`pnpm build`
- 首次结果：构建失败，阻塞点为 `/api/auth/[...nextauth]` 收集数据阶段，报错为生产模式拒绝 `NEXTAUTH_URL` 指向 `localhost`
- 修复后再次执行：`pnpm build`
- 结果：前端整体构建通过，静态页生成与构建追踪均完成
