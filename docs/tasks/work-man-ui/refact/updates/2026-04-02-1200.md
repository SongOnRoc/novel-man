# 本次做了什么

- 基于用户提供的 `/works/47` 桌面端与移动端截图，使用 pencil 产出一版“同一信息结构、仅重排”的线框预览。
- 桌面端线框：封面缩小为左列，右侧集中展示标题/Meta/Stats/主操作，减少卡片与留白。
- 移动端线框：将主动作确定为 `新建草稿（绑定当前作品）`，并保留底部 sticky 动作条，但将按钮形态轻量化（更接近 toolbar，避免主按钮过大占用内容区），同时压缩 Header 让 Tabs 内容区更早进入视野。

# 为什么这么做

- 现页面存在“一个信息点占一个大卡”的信息密度问题，尤其移动端首屏被低价值容器挤占。
- 业务操作逻辑决定移动端优先级：先草稿写作，后发布为章节，因此移动端应把 `新建草稿` 作为主动作。
- 维护成本约束：不做桌面端/移动端两套设计，采用同一信息结构，通过响应式重排解决。

# 验证方式与结果

- 使用 pencil 生成并截图确认：
  - 桌面端布局达到“信息更紧凑、容器更少”的目标，用户反馈“桌面端基本认可”。
  - 移动端采用 sticky 动作条后，按钮分布更合理（主按钮 `新建草稿` + `更多`），且 Tabs 内容区上移。
  - 新增定义：Header 收缩态仅收缩顶部信息条，不移动底部动作入口（避免入口位置跳变）。
