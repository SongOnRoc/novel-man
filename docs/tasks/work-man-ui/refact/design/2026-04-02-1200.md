# 作品管理页（/works/:id）移动端按钮与比例优化（线框稿）

时间：2026-04-02 12:00

本文件记录基于 `/works/47` 当前页面截图做的线框级优化方向确认，用于后续落地实现。

## 背景

- 现状问题：移动端上半区信息密度偏低，按钮区域占比不合理，导致「展示区」挤占「管理区（Tabs 内容）」首屏空间。
- 操作逻辑约束：移动端默认开始写作应是创建“绑定当前作品的草稿”，草稿完成后再发布为章节。
- 维护成本约束：不希望桌面端/移动端两套设计，优先同一信息结构，仅通过响应式重排（reflow）适配。

## 目标

- 保持大框架不变：上半区作品信息 + 下半区内容管理 Tabs。
- 提升移动端管理效率：首屏更快进入 Tabs 内容区。
- 按操作逻辑调整按钮优先级：`新建草稿` 为主动作。

## 方案（已预览）

### 桌面端（已基本认可）

- 封面缩小为左侧窄列，右侧为：标题 + Meta 行（连载状态/ID/更新时间）+ Stats 行（字数/章节/已发布/更新时间）+ 主操作按钮组。
- 通过“减少卡片数量、压缩留白、合并统计展示”的方式提升信息密度。

对应预览图：

- `docs/tasks/work-man-ui/refact/design/XOEEA.png`

### 移动端（方案 1：底部 Sticky 动作条，主动作=新建草稿）

- Header 只保留：标题、Meta、Stats，压缩高度。
- Tabs 内容区上移，提升“管理区”首屏占比。
- 底部固定 `StickyActions`（轻量化）：
  - 主按钮：`新建草稿`（绑定当前作品）
  - 次入口：`更多`（用于承载扩展动作；当前阶段可先保留，但不强制填满）

移动端 Sticky 主按钮不做“占满整条的巨型按钮”，而是保留 sticky 容器但降低按钮视觉重量与高度（更接近 toolbar），避免抢占内容区空间。

对应预览图：

- `docs/tasks/work-man-ui/refact/design/dBpvw.png`

注：Header 收缩态的交互规则已明确为“仅收缩顶部，不移动底部动作区（更多保持右侧）”。当前阶段为避免设计资产冗余，未单独保留收缩态示意图。

### 移动端（更多打开态）

- 点击底部 sticky 右侧 `更多` 后，使用底部浮层样式展开，不改变主页面布局。
- 当前更多菜单项与客户端保持一致，仅承载当前未直接暴露在 sticky 中的动作：
  - `新建章节`
  - `编辑作品`
- 浮层底部提供 `关闭` 按钮。

说明：更多打开态使用单独示意图展示，不覆盖默认状态。

对应预览图：

- 默认态（More Closed）：`docs/tasks/work-man-ui/refact/design/dBpvw.png`
- 打开态（More Open, Bottom Sheet）：`docs/tasks/work-man-ui/refact/design/G5YEB.png`
