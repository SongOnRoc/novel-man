# 作品详情页跨端 UI 重构设计

## 背景

当前 `frontend/src/app/(main)/works/[id]/page.tsx` 已承载作品详情与作品管理首页职责，但页面存在明显的 UI 结构问题：

- 顶部区域由返回区、封面占位卡、状态徽标、简介、4 个统计卡、4 个操作按钮同时竞争注意力
- 下方内容管理区再次使用大卡片包裹 tabs 与列表，导致页面层级过厚
- 章节与草稿列表使用胖卡片渲染，单项信息密度过低
- 移动端基本是桌面大卡片的纵向堆叠，容易出现单个数字或少量信息占满首屏的问题

## 目标

- 不减少任何实质信息与现有交互入口
- 将页面重构为“上方作品信息区 + 下方管理工作区”的上下布局
- 通过更轻的容器、更紧凑的指标布局和行式列表，提升桌面端与移动端的信息效率
- 保持现代、克制、跨端一致的视觉语言，避免再次堆出卡片森林

## 设计原则

1. 信息不减，容器减重
2. 主次分明，只有标题与当前主操作拥有最强强调
3. 统计信息保留，但不再以 4 张大卡片承载
4. 列表项改为紧凑 row，而不是每项一个独立厚卡片
5. 移动端单独优化密度与换行策略，而不是机械压缩桌面布局

## 页面结构

### 顶部作品信息区

- 保留返回入口和“作品管理”标签
- 主体内容改为单一信息区，不再使用封面占位大卡
- 作品标题、简介、状态、更新时间、作品 ID 放在同一语义块中
- 操作按钮保留为：新建草稿、新建章节、编辑作品信息、删除作品
- 统计信息保留 4 项，但改为紧凑指标网格，弱化边框和说明文案层级

### 下方作品管理区

- 保留 `Tabs` 结构与全部 tab 内容
- 去除厚重的外层卡片与大段说明对视觉焦点的抢占
- `TabsList` 改为更轻的 segmented control 风格
- 各 tab 内容保留原有入口与描述，但收敛标题区高度

### 列表项

- 章节列表、草稿列表使用统一的行式布局
- 左侧展示主信息，右侧保留进入详情的箭头
- 次级元信息压缩为一行或两行内解决，减少垂直空间浪费
- 继续保留现有的章节序号、字数、更新时间、状态等信息

## 跨端策略

- 桌面端：顶部作品信息区横向展开操作区，统计区紧贴标题区下方
- 移动端：顶部操作区改为两列按钮或纵向紧凑排列，统计区使用 2 列小块，不允许单项独占一整屏
- Tabs 在移动端继续可横向滚动，但整体高度与内边距缩小

## 范围说明

### 本次要做

- 重构 `frontend/src/app/(main)/works/[id]/page.tsx` 的页面布局与视觉层级
- 压缩统计、列表、placeholder 模块的空间占用
- 保持所有现有文案、入口、业务逻辑与数据不丢失

### 本次不做

- 不新增后端接口
- 不减少 tab 数量或移除现有数据字段
- 不改作品详情页之外的子页面布局
