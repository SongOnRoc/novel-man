# 章节目录页补完设计

## 背景

当前章节目录页已经完成从“章节管理页”到“章节目录骨架”的第一阶段重构，但仍停留在平铺列表层面：

- `ChapterTocTree` 仍然只是简单章节列表，不是分卷树
- `ChapterDirectoryToolbar` 的全部展开 / 全部折叠仍是占位按钮
- 目录页缺少“当前章节自动定位”能力

在章节阅读页、编辑页、分析工作区和整体构建都已推进后，目录页已经成为当前章节系统中最明显的产品能力缺口。

## 目标

- 将章节目录页升级为可用的分卷目录树
- 支持全部展开 / 全部折叠 / 搜索过滤
- 支持当前章节自动定位：自动展开所属分卷并高亮当前章
- 保持现有章节操作入口不倒退，包括进入阅读、编辑、调整章节号和删除

## 范围

### 本次要做

- 在前端将章节数据按 `volumeId` 分组为目录树
- 为目录树补充分卷标题、分组折叠状态和章节条目高亮
- 在目录页引入基于 URL 的 `currentChapterId` 自动定位能力
- 为目录工具条接入真实的全部展开 / 全部折叠行为
- 让搜索结果以“过滤后的树”方式展示，而不是直接平铺过滤
- 更新目录页测试，覆盖树结构、展开折叠、当前章定位和搜索行为

### 本次不做

- 不引入新的后端接口
- 不补最近访问记录持久化
- 不实现目录拖拽排序
- 不扩展“更多操作”的新产品功能
- 不在本轮清理 preview 页遗留职责

## 用户交互设计

### 1. 分卷树展示

- 目录页按分卷渲染章节组
- 每个分卷组有标题、章节数和展开 / 折叠入口
- 组内展示章节条目，条目仍保留进入阅读页和更多操作菜单
- 若当前作品的所有章节都没有 `volumeId`，则 UI 退化为纯章节目录列表：
  - 不显示分卷树容器
  - 不显示分卷标题与展开 / 折叠控件
  - 工具条中的全部展开 / 全部折叠按钮隐藏

### 1.1 目录分页

- 章节目录需要分页展示，避免页面无限向下滚动
- 分页作用于“当前过滤后的可见目录结果”，而不是原始章节全集
- 当存在分卷数据时，分页单位是“分卷组”而不是单条章节，避免一个分卷被切到两个分页中
- 当不存在分卷数据时，分页单位退化为“章节条目”
- 切换搜索词、当前章节定位或展开状态后，若当前页超出范围，应自动回到第 1 页
- 若存在 `currentChapterId`，分页需要优先保证目标章节可见：
  - 分卷树模式下，自动切换到当前章节所属分卷所在页
  - 纯章节目录模式下，自动切换到当前章节所在条目页
  - 完成切页后，再执行高亮与滚动到可视区域

### 2. 当前章节自动定位

- 目录页通过 `currentChapterId` 查询参数确定当前章
- 若参数命中当前作品中的某个章节：
  - 自动切换到其所在分页
  - 自动展开其所属分卷
  - 对目标章节条目高亮
  - 在渲染后将其滚动到可视区域
- 若参数缺失或无效：
  - 不报错
  - 回退为普通目录模式
  - 默认展开首个非空分卷

### 2.1 展开状态优先级

为避免搜索、当前章节定位和手动折叠相互冲突，本次明确以下优先级：

1. 搜索命中态优先级最高
   - 只要搜索词非空，所有命中分卷都必须展开
   - 搜索结果下不允许把命中分卷折叠到不可见
   - 点击 `全部折叠` 时，仅折叠非命中分卷；命中分卷继续展开
2. 当前章节定位次之
   - 在无搜索词时，若存在 `currentChapterId`，其所属分卷必须保持展开
   - 用户不能将当前章节所属分卷折叠到不可见
3. 手动展开 / 折叠状态再次之
   - 仅在不影响搜索命中和当前章节可见性的前提下生效
4. 默认展开为兜底规则
   - 当无搜索、无当前章节且无手动状态时，默认展开首个非空分卷

搜索清空后，不保留“搜索期间的临时展开结果”，而是恢复到搜索前的手动展开状态，再重新应用当前章节定位规则。

若当前章节定位导致自动切页，则该切页优先级高于“搜索词变化后回到第 1 页”的默认规则。

### 3. 全部展开 / 全部折叠

- `全部展开`：只作用于当前页可见的分卷组，不跨页修改其他分页的展开状态
- `全部折叠`：只作用于当前页可见的分卷组，不跨页修改其他分页的展开状态；若存在当前章节，仍保留其所属分卷展开，避免自动定位失效

之所以限制为“当前页可见分卷组”，是为了让分页后的交互可预期、可解释，也便于测试覆盖。

### 4. 搜索行为

- 搜索框继续支持按关键词过滤
- 搜索前先做 `trim()` 和小写归一化
- 章节匹配字段：
  - `title`
  - 章节展示编号文本（例如“第一章”“第二章”）
- 分卷匹配字段：
  - 分卷展示标题（例如“未分卷”“第 1 卷”）
- 命中章节时，保留其所属分卷并自动展开该组，仅展示命中的章节条目
- 命中分卷标题时，保留整组章节
- 若同一分卷同时命中分卷标题和组内章节，则按“命中分卷标题”处理，展示整组，避免结果被意外裁切
- 无结果时展示目录空状态，而不是空白列表

## 数据与状态设计

### 数据来源

- 仍沿用 `useChapterList({ workId, page: 1, limit: 9999 })` 一次性获取全量章节，并在前端完成目录级分页
- 本次不依赖新的分卷接口

### 目录视图模型

目录页在页面层构建一层目录视图模型，输出：

- 分卷组列表
- 每组的章节数组
- 当前章节 id
- 默认展开分卷集合
- 搜索后可见分卷集合
- 是否存在分卷数据的布尔标记
- 当前页可见目录项

### 分卷标题策略

当前章节数据可用字段以 `volumeId` 为主，因此本轮使用稳定占位标题：

- `volumeId` 为空：`未分卷`
- `volumeId` 有值：使用“排序后出现顺序”的展示序号，而不是直接展示原始 `volumeId`

具体规则：

- 先提取所有非空 `volumeId`
- 按原始 `volumeId` 数值升序排序
- 为排序后的每个 `volumeId` 分配连续展示序号 `1..n`
- 最终展示为 `第 {displayIndex} 卷`

这样可以避免直接暴露数据库主键、稀疏编号或不可读的原始 `volumeId`。内部仍使用原始 `volumeId` 作为稳定分组 key。

后续若作品侧补到真实分卷元数据，只替换标题生成逻辑即可。

### 分卷与章节排序规则

- 分卷顺序：
  - `未分卷` 固定排在最前
  - 其余分卷按原始 `volumeId` 数值升序排列
- 组内章节顺序：
  - 先按 `displayOrder` 升序
  - 若相同，再按 `id` 升序兜底

这样可保证目录顺序稳定，并与当前章节页已有排序逻辑保持一致。

### 状态边界

目录页页面组件负责：

- 查询参数解析
- 当前章节 id 推导
- 展开分卷状态维护
- 搜索过滤状态
- 当前分页状态维护
- 将目录树数据传给 `ChapterTocTree`

`ChapterDirectoryToolbar` 只负责交互触发，不持有树状态。

`ChapterTocTree` 负责展示目录树、分卷节点和章节条目，不负责决定全局状态来源。

当不存在任何分卷数据时，页面层直接将分页后的章节列表传给目录组件，目录组件以“纯章节目录模式”渲染。

## 错误处理与退化策略

- `currentChapterId` 无效时不抛错，只退化为普通目录模式
- 搜索无结果时展示明确空状态提示
- 数据尚未加载完成时维持现有 loading 展示
- 若没有任何章节，继续沿用现有“前往作品草稿 / 导入章节”的空状态
- 若没有任何分卷数据，不展示空的分卷壳层，而是直接退化为纯章节目录列表

## 验收标准

- 目录页显示为分卷树，而非简单平铺列表
- 当不存在任何分卷数据时，页面退化为纯章节目录，不显示分卷树 UI
- 当前章节可通过 URL 参数自动定位并高亮
- 全部展开 / 全部折叠真实生效
- 搜索结果以树形式展示，并能保留目录上下文
- 目录结果支持分页，不需要无限向下滚动
- 现有章节入口与操作菜单能力不倒退
- 目录页测试通过，且不破坏当前整体 `pnpm build`

## 风险与注意事项

- 当前缺少真实分卷名称，需接受“第 N 卷 / 未分卷”的阶段性展示
- 当前章节定位若直接依赖 DOM 滚动，需要避免在测试环境中造成不稳定；建议只在元素存在时调用滚动方法
- 搜索、自动展开和手动折叠会同时作用于目录树，需要明确优先级，避免状态互相覆盖
