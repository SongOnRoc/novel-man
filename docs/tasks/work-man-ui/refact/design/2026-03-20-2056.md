# 章节系统统一设计方案

## 设计目标

章节系统后续需要同时承载：

- 卷 / 章目录浏览
- 单章节阅读与编辑
- 整章提取大纲 / 角色
- 段落级碎片选择后提取
- PC 与移动端都可完成核心任务

本方案的目标不是继续扩展当前“章节管理页”，而是重新定义章节系统的页面职责和跨端交互模型，避免系统继续演化成展示型工作台。

## 一、核心原则

### 1. 一页只服务一个主任务

- 目录页负责结构定位。
- 单章节页负责正文处理。
- 分析工作区负责结构提取结果。
- 段落选择模式负责确定分析输入范围。

### 2. 不做两套产品，只做一套任务流

- 桌面端与移动端允许使用不同容器。
- 但主任务、状态流转、能力边界保持一致。

### 3. 辅助能力必须后置

- 目录、分析、更多操作都不能默认与正文或主列表并列争夺主空间。
- 通过抽屉、sheet、dialog、模式切换承载。

### 4. 页面通过模式切换解决复杂度，不通过区域堆叠解决复杂度

- 浏览态
- 选择态
- 分析态
- 编辑态

这些模式必须边界清晰，不能平铺混合。

## 二、章节系统拆分为四个单元

### 1. 章节目录页：负责“找”

页面使命：

- 浏览卷章结构
- 搜索与定位章节
- 折叠 / 展开卷
- 跳转到目标章节
- 做少量目录级操作

不承担：

- 大量统计卡
- 分析结果展示
- 段落级交互
- 正文级复杂操作

#### 目录页结构

1. 轻量页头
2. 目录工具条
3. 目录主体树
4. 必要时的空状态 / 搜索无结果区

#### 目录页规则

- 有分卷：按 `卷 -> 章` 两级结构展示。
- 无分卷：直接展示章节目录。
- 未分卷章节：单独归入 `未分卷` 分组。
- 默认不展开全部卷，优先展开当前卷或最近访问卷。
- 搜索命中时自动展开相关卷。

### 2. 单章节页：负责“读 / 写”

页面使命：

- 阅读当前章节
- 编辑当前章节
- 切换上下章
- 打开目录
- 打开分析工作区
- 进入段落选择模式

不承担：

- 目录树常驻并列
- 大量作品级上下文说明
- 复杂统计卡

#### 单章节页结构

1. 顶部轻导航条
2. 正文工作区
3. 按需展开的目录层 / 分析层

#### 单章节页规则

- 正文永远是主角。
- 目录只作为辅助导航入口存在。
- 分析只作为辅助工作区存在。
- 段落级提取必须先进入选择模式。

### 3. 分析工作区：负责“提”

页面使命：

- 接收输入对象
- 选择分析类型
- 展示结果
- 保存 / 应用 / 关闭

输入对象分两类：

- 当前整章
- 当前已选段落集合

#### 分析工作区结构

1. 顶部上下文条
2. 分析类型切换区
3. 结果主体区
4. 底部操作区

#### 分析工作区规则

- 不负责选择输入范围。
- 不负责目录导航。
- 不长期抢占正文主空间。
- 结果结构优先保证可扫描、可复核、可保存。

### 4. 段落选择模式：负责“选”

页面使命：

- 从当前章节中圈定分析输入范围

核心流程：

`进入选择模式 -> 选择若干段 -> 确认分析类型 -> 进入分析工作区`

#### 选择模式规则

- 这是显式模式，不是普通阅读态里的附加小功能。
- 段落是基础选择单元。
- 进入选择模式后，正文进入可选择状态。
- 退出方式只有：取消或开始提取。

## 三、状态流转

### 1. 目录到章节

`章节目录页 -> 点击某章 -> 单章节页`

### 2. 章节到分析

`单章节页 -> 提取整章 -> 分析工作区`

### 3. 章节到片段提取

`单章节页 -> 进入选择模式 -> 选择段落 -> 进入分析工作区`

### 4. 分析回流

`分析工作区 -> 关闭 -> 回到单章节页`

### 5. 选择模式回流

- 取消：回到单章节普通态
- 开始提取：进入分析工作区

## 四、桌面端承载方式

### 1. 章节目录页

- 目录作为主内容常驻页面中央。
- 搜索和折叠控制放在目录工具条。
- 不再保留大面积上下文卡片和信息展示区。

### 2. 单章节页

- 正文居中优先。
- 目录通过侧抽屉或浮层打开。
- 分析通过右侧面板打开。
- 不采用常驻左目录 + 中正文 + 右分析三栏长期并列模式。

### 3. 分析工作区

- 右侧面板。
- 默认关闭，按需打开。
- 打开后正文仍保持可读宽度。

### 4. 段落选择模式

- 顶部固定选择工具条。
- 正文可选。
- 主动作清晰暴露。

## 五、移动端承载方式

### 1. 章节目录页

- 目录仍是主内容。
- 顶部极度压缩，只保留返回、页面名、搜索、更多菜单。
- 卷与章节保持轻量树形层次，不做多层卡片套叠。

### 2. 单章节页

- 正文全宽优先。
- 顶部轻导航。
- 不常驻目录，不常驻分析面板。

### 3. 目录入口

- 全屏目录层。
- 用户完成定位与跳转后回到正文。

### 4. 分析工作区

- 全屏 `Sheet` / `Dialog`。
- 作为独立任务层进入与退出。

### 5. 段落选择模式

- 顶部显示选择状态。
- 底部固定主操作栏。
- 中间正文保持可读、可点选。

## 六、需要明确废弃的旧模式

后续章节系统设计中，以下模式不得继续引入：

- 首屏统计卡铺满
- 章节页继续堆说明块 / 洞察卡 / 管理卡片
- hover 才出现关键操作
- 多按钮自动换行作为移动端方案
- 目录、正文、分析、说明长期并列在同一页面
- 把章节目录页继续当成综合管理后台页

## 七、建议的后续设计顺序

1. 重新定义章节目录页结构
2. 重新定义单章节页结构
3. 设计分析工作区组件模型
4. 设计段落选择模式状态机
5. 再决定现有 `chapters/page.tsx`、预览页、编辑页如何拆分与复用

## 结论

章节系统应该被定义为一套清晰的任务流，而不是一个越来越重的工作台页面：

- 目录页负责找
- 单章节页负责读 / 写
- 分析工作区负责提
- 段落选择模式负责选

只要守住这四个边界，后续再增加提纲、角色、事件、设定等能力，也不会轻易把系统重新做乱。
