### 2.4 🚀 通用导入服务实现

#### 2.4.1 提示词导入服务

```go
// backend/internal/services/prompts/import_service.go

type PromptImporter struct {
    service prompts.PromptService
    parser  *parsers.Parser
    mapper  *upload.ModelMapper
}

func (i *PromptImporter) Import(ctx context.Context, file *multipart.FileHeader, userID uint) (*contracts.ImportResult, error) {
    // 创建回调函数处理不同文件类型
    callback := func(fileType upload.FileType, content []byte, filename string) ([]interface{}, error) {
        switch fileType {
        case upload.FileTypeJson:
            return i.mapper.MapFromJson(content, reflect.TypeOf(models.Prompt{}), userID)
        case upload.FileTypeTxt, upload.FileTypeMd:
            return i.mapper.MapFromText(content, filename, reflect.TypeOf(models.Prompt{}), userID)
        default:
            return nil, nil
        }
    }
    
    // 使用回调函数解析文件
    items, err := i.parser.ParseWithCallback(file, callback)
    if err != nil {
        return nil, err
    }
    
    // 保存到数据库
    for _, item := range items {
        prompt, ok := item.(*models.Prompt)models.Prompt)
        if !ok {
            result.Failed++
            result.Errors = append(result.Errors, "invalid prompt data")
            continue
        }

        if err := i.service.Create(ctx, prompt); err != nil {
            result.Failed++
            result.Errors = append(result.Errors, err.Error())
        } else {
            result.Success++
        }
    }
    
    return result, nil
}
```

## 3. API 端点详细设计

### 3.1 提示词导入 API

**端点**: `POST /api/v1/prompts/import`

**请求头**:
```
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

**请求体**:
```
file: <文件>
```

**响应** (200 OK):
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "success": 5,
    "failed": 1,
```

## 4. 🔄 架构优势

### 4.1 零重复代码设计

#### ❌ 传统方案问题
```go
// 每个业务模块都要重复实现
// Prompt 模块
func processJson(content []byte) ([]*models.Prompt, error) { ... }
func processText(content []byte) ([]*models.Prompt, error) { ... }

// Work 模块  
func processJson(content []byte) ([]*models.Work, error) { ... }
func processText(content []byte) ([]*models.Work, error) { ... }

// Chapter 模块
func processJson(content []byte) ([]*models.Chapter, error) { ... }
func processText(content []byte) ([]*models.Chapter, error) { ... }
```

#### ✅ 新方案优势
```go
// 只需在模型上添加标签
type Prompt struct {
    Title string `json_field:"title"`
    Content string `json_field:"content"`
}

// 业务模块复用通用映射器
func (i *PromptImporter) Import(ctx, file, userID) (*ImportResult, error) {
    callback := func(fileType, content, filename) ([]interface{}, error) {
        return i.mapper.MapFromJson(content, reflect.TypeOf(Prompt{}), userID)
    }
    // ... 其他逻辑
}
```

### 4.2 类型安全保障

- **编译时检查**: 标签配置错误在编译时发现
- **自动类型转换**: 反射自动处理类型匹配
- **零运行时错误**: 避免手动类型转换错误

### 4.3 高度可扩展性

- **新增业务模块**: 只需模型标签配置
- **新文件格式**: 添加对应解析器
- **灵活配置**: 通过标签控制映射行为

## 5. 数据流程

### 5.1 提示词导入流程

```
1. 用户选择文件 → 前端验证
2. 上传文件 → API Gateway
3. 认证中间件 → 验证用户身份
4. 文件验证中间件 → 验证文件类型和大小
5. 控制器接收 → 调用导入服务
6. 通用解析器解析文件内容
7. 反射器根据标签自动创建模型
8. 批量创建 → 保存到数据库
9. 返回结果 → 成功/失败统计
```

### 5.2 错误处理流程

```
1. 文件验证失败 → 返回 400 错误
2. 解析失败 → 记录错误，继续处理其他文件
3. 映射失败 → 记录错误，继续处理
4. 数据库错误 → 记录错误，继续处理
5. 返回结果 → 包含所有错误信息
```
