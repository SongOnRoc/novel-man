# 文件上传和导入功能实施计划

## 执行摘要

本文档提供了为小说管理系统后端添加通用文件上传和导入功能的完整实施计划。该功能将支持提示词、作品和章节三个核心模块的数据导入，支持多种文件格式（.txt, .md, .json, .zip）。

## 1. 项目目标

### 1.1 主要目标
- 为系统添加通用的文件上传和导入能力
- 支持多种文件格式的解析和处理
- 提供统一的导入接口和错误处理机制
- 确保数据安全和系统稳定性

### 1.2 成功标准
- 所有三个模块（提示词、作品、章节）都能成功导入数据
- 支持的文件格式都能正确解析
- 导入成功率 > 95%
- 单个文件处理时间 < 5秒
- 通过所有安全性测试

## 2. 🚀 技术方案概述

### 2.1 架构设计
采用分层架构，包括：
- **工具层**: 通用文件处理工具（解析、验证、映射）
- **服务层**: 各模块的导入服务实现
- **控制器层**: API 端点处理
- **中间件层**: 认证、验证、限流

### 2.2 核心组件
1. **文件解析器**: 支持 txt, md, json, zip 格式
2. **文件验证器**: 类型、大小、内容验证
3. **🚀 模型映射器**: 基于反射的自动模型创建
4. **导入服务**: 各模块的具体导入逻辑导入逻辑
5. **API 端点**: RESTful 接口

### 2.3 🔥 架构创新

#### 反射+标签映射系统
```go
// 只需在模型上添加标签
type Prompt struct {
    Title string `json_field:"title"`
    Content string `json_field:"content"`

// 业务模块复用通用映射器
func (i *PromptImporter) Import(ctx, file, userID) (*ImportResult, error) {
    callback := func(fileType, content, filename) ([]interface{}, error) {
        return i.mapper.MapFromJson(content, reflect.TypeOf(Prompt{}), userID)
    }
    // ... 其他逻辑
}
```

## 5. 🚀 架构优势

### 零重复代码设计
- **传统问题**: 每个业务模块都要重复实现 `processJson`、`processText` 函数
- **新方案**: 只需在模型上添加 `json_field` 标签，复用通用映射器

### 类型安全保障
- **编译时检查**: 标签配置错误在编译时发现
- **自动类型转换**: 反射自动处理类型匹配
- **零运行时错误**: 避免手动类型转换错误

### 高度可扩展性
- **新增业务模块**: 只需模型标签配置
- **新文件格式**: 添加对应解析器
- **灵活配置**: 通过标签控制映射行为
