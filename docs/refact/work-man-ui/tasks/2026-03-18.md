# 为什么这么做

- proposal 的阶段 1 要求先做前端收口：outline/world 必须统一壳层，避免重复 header/滚动冲突。
- proposal 的核心决策之一是“display_order 是章节顺序唯一权威来源”，需要尽快消除 `index+1` 这类不稳定章号来源。
- 章节正序/倒序切换是后续发布提示、重排插入顺延等能力的前置依赖；先用前端排序+URL 状态落地最小闭环。
