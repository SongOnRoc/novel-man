## 1.2 本轮核心落地（草稿收敛闭环）

- 作品草稿统一收敛到 `/works/[id]/drafts` 体系：列表、新建、编辑、发布。
- 关键跳转点已做上下文注入，避免作品草稿误跳全局编辑页：
  - `DraftList`/`DraftCard` 的编辑入口走 `getDraftEditHref` 注入策略。
  - `useDraftCreationController` 在作品页覆盖 `getDraftEditPath`。

## 1.3 残留入口清扫结论
- `/drafts?workId=...` 旧入口：在 `frontend/src/**/*.ts(x)` 范围内已查无残留。
- `/drafts/${id}/edit` 硬编码：仅保留在“默认全局路径/全局草稿箱/快捷入口分流”等合理位置，作品上下文通过注入覆盖。

## 1.4 验证结果（定向测试）
定向 vitest 已通过（5 files / 12 tests），覆盖：

# 2) 需求文档（PRD）——作品管理（工作台）

## 2.1 背景与问题
当前作品相关能力分散在多个页面/模块中，风格与交互不统一。需要以“单作品工作台”为中心统一信息架构与操作路径，确保用户在同一上下文内完成高频创作管理（`docs/design/作品管理.md:4-11,20-29`）。

## 2.2 目标
1. `/works/[id]` 成为单作品工作台首页（总览）。
2. 工作台内统一模块导航与布局：章节 / 草稿 / 大纲 / 角色 / 设定（世界观设定）。
3. 草稿边界清晰：
   - 作品内草稿：已绑定当前作品、未发布章节（`docs/design/作品管理.md:110-115`）
   - 全局 `/drafts`：未绑定作品的灵感草稿箱（`docs/design/作品管理.md:116-125`）
4. 章节模块以章节顺序为主排序，并支持正序/倒序切换（`docs/design/作品管理.md:153-160`）。
5. 关键主流程打通：进入作品 → 草稿 → 发布为章节（`docs/design/作品管理.md:136-142`）。

## 2.3 非目标（本期不做/暂缓）
- 不直接把大纲/world 的 mock 原型逻辑当作生产逻辑扩展（只做“壳层统一 + 最小闭环”）。
- 不强行一次性完成所有 AI 提取落地（但要为链路预留交互位与状态）。

## 2.4 用户故事（核心）
### US-1 进入作品工作台
用户从作品列表进入某作品后，能立即看到作品封面、基础信息、统计信息与高频操作入口（新建章节/新建草稿/编辑作品信息）。

### US-2 管理作品草稿
用户在“草稿”标签内查看当前作品草稿列表，可继续编辑、发布为章节、删除草稿。

### US-3 管理章节目录
用户在“章节”标签内按章节顺序管理章节，支持正序/倒序；可新建章节并自动递增编号（`docs/design/作品管理.md:162-169`）。

### US-4 管理创作资产（大纲/角色/设定）
用户在对应标签内查看与维护资产，交互结构与工作台保持一致，具备统一的工具栏/空态/加载态/错误态（`docs/design/作品管理.md:91-106,336-347`）。

## 2.5 信息架构与页面结构（必须一致）
### 2.5.1 总体布局
- 上半区：作品基础信息区（左封面右信息）（`docs/design/作品管理.md:15-76`）
- 下半区：标签页模块区（章节/草稿/大纲/角色/设定）（`docs/design/作品管理.md:20-28,81-90`）

### 2.5.2 标签顺序（固定）
1) 章节 2) 草稿 3) 大纲 4) 角色 5) 设定（`docs/design/作品管理.md:81-90`）

### 2.5.3 模块通用结构（统一模板）
每个模块必须包含：
- 模块标题、模块说明
- 顶部工具栏（搜索/排序/筛选/新建/视图切换按需）
- 内容区
- 空状态/加载态/错误态（`docs/design/作品管理.md:91-106,336-342`）

## 2.6 关键业务规则

### 2.6.1 草稿边界规则（强约束）
- 作品页草稿：仅显示已绑定当前作品、未发布草稿（`docs/design/作品管理.md:110-115`）
- `/drafts`：仅显示未绑定作品（灵感草稿）（`docs/design/作品管理.md:116-125`）
- 作品上下文“编辑草稿”必须进入 `/works/[id]/drafts/[draftId]/edit`，不允许跳 `/drafts/[draftId]/edit`（除非草稿未绑定作品）。

### 2.6.2 章节排序规则（强约束）
- 默认按章节顺序正序；允许倒序；更新时间只能作为辅助信息（`docs/design/作品管理.md:153-161`）

### 2.6.3 新建章节默认逻辑（强约束）
- 自动识别最大章节序号并递增生成默认标题（`docs/design/作品管理.md:162-169`）

### 2.6.4 AI 提取交互（阶段性约束）
必须预留并统一状态：
- 提取中 / 完成 / 失败与重试（`docs/design/作品管理.md:343-347`）
链路步骤参考（`docs/design/作品管理.md:224-235`）。

## 2.7 交互与响应式要求
- 桌面端强调效率与并列信息；章节项二级操作建议右侧抽屉或展开面板承载（`docs/design/作品管理.md:198-213`）
- 移动端采用底部操作面板或次级页承载扩展操作，避免卡片堆按钮（`docs/design/作品管理.md:214-223`）
- 上半区移动端改为纵向堆叠，标签栏可横滑（`docs/design/作品管理.md:317-326`）

## 2.8 验收标准（可测试）
### A. 路由与职责
- `/drafts` 只显示未关联作品草稿
- `/works/[id]/drafts` 只显示当前作品草稿
- 作品内新建草稿：进入 `/works/[id]/drafts/new`
- 作品内编辑草稿：进入 `/works/[id]/drafts/[draftId]/edit`
- 发布草稿成功：进入 `/works/[id]/chapters`

### B. 章节体验
- 章节列表默认按章节顺序正序；可切倒序；排序状态可见
- 新建章节默认标题/序号递增符合规则

### C. 状态一致性
- 关键 mutation 后（草稿发布/章节新增/删除等）作品统计与列表保持一致（需定义刷新策略）

### D. 测试要求
至少具备页面级测试覆盖：
- 工作台入口 `/works/[id]`：总览渲染、模块切换
- 草稿模块主流程：新建 → 编辑 → 发布 → 章节列表可见
- 章节模块：排序切换、新建逻辑

## 4.1 章节模块补齐强约束规则（优先级最高）

- 落地“按章节顺序排序 + 正序/倒序切换”
