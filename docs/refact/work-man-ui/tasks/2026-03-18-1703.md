# 本次做了什么

- 将 `PageHeader` 升级为更通用的页头实现：支持通过 `backButton` 配置注入响应式返回按钮，而不是只靠简单的 `showBackButton/backHref`。
- 新增通用返回组件 `frontend/src/components/common/layout/ResponsiveBackButton.tsx`：
  - 移动端仅显示箭头图标
  - 桌面端显示箭头 + 文案 `返回作品管理`
  - 点击固定跳转到 `/works/[id]`
- 将多个作品管理子页面接入统一返回按钮：
  - `chapters`
  - `drafts`
  - `characters`
  - `outline`
  - `world`
  - `edit`
  - `drafts/new`
- 编辑器页也对齐返回目标：
  - `frontend/src/app/(main)/works/[id]/drafts/[draftId]/edit/page.tsx`
  - `frontend/src/app/(main)/works/[id]/chapters/[chapterId]/edit/page.tsx`
  - 统一回到 `/works/[id]`，并给工具栏返回按钮补上 `返回作品管理` 桌面文案。

# 为什么这么做

- 返回按钮原本分散在不同页面与工具栏里，表现不一致，有的返回列表页，有的返回历史页，不符合“所有作品管理子页面都返回作品管理页”的要求。
- 通过抽离统一按钮 + 升级 `PageHeader`，可以在不重新把子页面套回统一壳层的前提下，收敛交互一致性。
