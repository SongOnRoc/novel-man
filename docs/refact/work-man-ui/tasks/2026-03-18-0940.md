# 本次做了什么

- 阶段 0：新增“章节编号样式 + 标题归一化工具”与单测（中文数字 1-9999、模板校验、章号剥离、冲突检测）。
- 阶段 0：新增本地持久化（localStorage）方案：全局默认 + 作品覆盖，并提供“生效配置”读取与模板解析工具。
- 阶段 4（前置落地）：作品草稿编辑页发布弹框接入上述能力：发布时提示“将发布为第X章”，若用户标题含冲突章号则强制修正；并在 publish 前先更新草稿 title，确保后端发布后的 chapter.title 可靠。

# 为什么这么做

- proposal 明确“章节标题 = 编号前缀 + 标题后缀”，且发布时必须提示“将发布为第X章”，不能绕过冲突章号。
- 后端当前使用 draft.title 作为 chapter.title；若不在 publish 前先更新草稿标题，最终章节标题无法被前端强约束。
- 先把编号/归一化能力沉到工具层，可被后续“章节重排（插入并顺延）”与“章节号展示”复用。
