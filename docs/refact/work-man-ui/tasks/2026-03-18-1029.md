# 本次做了什么

- 作品草稿列表页 `/works/[id]/drafts` 的发布入口改为使用 `PublishDraftDialog`：展示“将发布为第X章”，并在发布前先更新草稿标题（归一化后）再发布。
- 全局草稿编辑页 `/drafts/[id]/edit` 的发布流程改为两步：先选择作品，再进入 `PublishDraftDialog` 做标题归一化与冲突修正；发布前写入 `workId + title`，然后 publish。
- 全局草稿箱 `/drafts` 的“发布”改为先选作品再发布，并复用 `PublishDraftDialog` 的标题归一化/冲突修正逻辑。
- 补齐并调整单测 mocks：`WorkDraftsPage`、`DraftsPage` 新增 `useChapterList` / `useUpdateDraft` 的 mock，确保测试可运行。

# 为什么这么做

- proposal 阶段 4 的验收要求是“发布时必须提示将发布为第X章，并强制修正冲突章号；且为保证最终 chapter.title 正确，需要在 publish 前先更新 draft.title”。
- 之前仅 `/works/[id]/drafts/[draftId]/edit` 接入了发布弹框；本次把同样的约束收口到列表页和全局草稿编辑/草稿箱，避免不同入口发布结果不一致。
