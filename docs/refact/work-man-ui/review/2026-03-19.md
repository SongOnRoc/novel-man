# Code Review Report

## 1) 变更摘要

- 本次前端改动重点在作品工作台收口：全局草稿箱职责收窄、作品章节页支持正序/倒序与章节重排、草稿发布前补充章节标题归一化。
- 新增了 `PublishDraftDialog` 与章节编号相关工具，尝试统一“第 X 章 + 标题后缀”的生成规则。
- `frontend/src/app/(main)/works/[id]/chapters/page.tsx` 引入了前端排序、全量章节拉取、重排弹窗和逐条更新逻辑。
- `frontend/src/app/(main)/drafts/page.tsx` 与 `frontend/src/app/(main)/drafts/[id]/edit/page.tsx` 都改成了“先选作品，再确认章节标题后发布”的两步流程。
- `frontend/src/app/(main)/works/[id]/outline/page.tsx` 与 `frontend/src/app/(main)/works/[id]/world/page.tsx` 仍保持独立 `PageHeader` 页面，没有按 proposal 接入工作台壳层。

## 2) 风险评估（结论先行）

风险等级：高。

当前改动方向基本正确，但存在一个会把草稿发布到错误作品的高风险状态问题；同时 outline/world 与 `docs/refact/work-man-ui/proposal.md` 的目标和验收标准不一致，说明这批改动还没有达到可放心合入的状态。

Top 风险点：

- 全局草稿发布时 `selectedWorkId` 可能沿用上一次选择，导致未关联草稿被误发布到错误作品。
- 章节重排仍采用逐条更新，真实环境中会出现部分成功、部分失败的中间态。
- outline/world 没有接入工作台壳层，和当前任务文档要求直接不一致。

## 3) 阻塞问题（必须修）

1. 位置：`frontend/src/app/(main)/drafts/page.tsx:316`、`frontend/src/app/(main)/drafts/page.tsx:324`、`frontend/src/app/(main)/drafts/page.tsx:436`
   问题：全局草稿发布流程存在“作品选择状态串单”。`handlePublish` 只有在草稿本身已有 `workId` 时才会设置 `selectedWorkId`，未关联草稿不会主动清空旧值；后续 `handleNextFromWorkSelect` 只校验该值是否存在，因此可能直接沿用上一次发布时选过的作品。
   影响：用户可能把当前草稿误发布到错误作品，属于实际数据落错位置的高风险 bug。
   建议修复：每次打开发布流程时都基于当前草稿重置选择状态；未关联草稿必须显式清空 `selectedWorkId`，并让选择框使用受控 `value` 而不是 `defaultValue`。

2. 位置：`frontend/src/app/(main)/works/[id]/outline/page.tsx:111`、`frontend/src/app/(main)/works/[id]/world/page.tsx:102`、`docs/refact/work-man-ui/proposal.md:13`、`docs/refact/work-man-ui/proposal.md:37`
   问题：实现与 proposal 不一致。proposal 明确要求 outline/world 接入 `WorkWorkspaceLayout + WorkModuleSection`，验收标准也要求展示工作台壳层与模块导航；但当前页面仅使用 `PageHeader`。
   影响：作品内模块导航和信息架构不统一，且当前实现不能满足本任务文档的验收标准。
   建议修复：要么按 proposal 接入工作台壳层，要么先同步更新 proposal/验收标准，避免“代码与任务定义不一致”的交付状态。

## 4) 建议改进（非阻塞）

1. 位置：`frontend/src/app/(main)/works/[id]/chapters/page.tsx:214`
   建议：章节重排逐条 `await updateChapterAsync` 的方案已知会产生部分成功的中间态，建议至少补充“处理中禁用关闭/返回、失败后明确提示哪些章节已写入”，后续最好补成后端批量接口或事务接口。

2. 位置：`frontend/src/app/(main)/works/[id]/chapters/page.tsx:124`
   建议：本地分页没有处理 `page > totalPages` 的越界情况，手改 URL 或删除数据后可能出现空白页；建议在页码越界时自动回退到最后一页。

3. 位置：`frontend/src/app/(main)/works/[id]/chapters/page.test.tsx:68`
   建议：当前测试直接 mock 了 `TOCChapterList`，导致真实目录组件里的下拉菜单、展示顺序、时间渲染都没有覆盖；建议补一组不 mock 列表组件的集成测试。

4. 位置：`frontend/src/components/common/layout/ResponsiveBackButton.tsx:23`
   建议：如果这里的语义是“导航到指定页面”，优先考虑 `Link` 方案而不是纯 `router.push`，这样更符合链接语义，也更利于可访问性和浏览器原生行为。
