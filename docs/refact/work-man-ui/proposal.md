# Task: work-man-ui
# Type: refact
# 开始日期: 2026-03-16

## 背景

作品工作台（/works/[id]）相关模块逐步落地后，出现“页面壳层不统一、章节顺序规则未落地、发布/标题规则不一致”的问题，导致用户对章节目录与发布结果的预期不稳定。

当前分支已具备工作台壳层组件（WorkWorkspaceLayout / WorkModuleSection），章节/草稿/角色等模块已部分接入，但 outline/world 仍为 mock 原型页；章节顺序与编号规则仍处于 UI 占位。

## 目标

- 先完成前端收口：outline/world 接入工作台壳层，保持路由结构不变。
- 以 display_order 作为章节顺序的唯一权威来源，前端不再使用 index+1 伪造章节号。
- 明确“章节标题 = 编号前缀 + 标题后缀”的结构，并在默认编辑态引导用户只填写后缀。
- 发布章节时必须提示“将发布为第X章”，若用户自定义标题中包含冲突章号则自动修正（不允许绕过）。
- 引入“章节编号样式”设置（全局默认 + 作品覆盖），支持常用样式与受限模板（仅允许 {N} 占位，单位/文字由样式决定，不做单独开关）。

## 范围

### 做什么

- 前端：outline/world 接入 WorkWorkspaceLayout + WorkModuleSection。
- 前端：章节列表支持正序/倒序切换（先做前端排序 + URL 状态）。
- 前端：章节号展示统一使用 displayOrder/display_order。
- 前端：草稿发布弹框补齐“第X章”提示与标题归一化修正。
- 前端：章节重排（插入并顺延）时同步修正章节 display_order 与标题前缀。
- 前端：章节编号样式（全局默认 + 作品覆盖）本地持久化。

### 不做什么

- 不在本阶段新增或改动后端接口（后端排序参数 / 批量重排接口留到后续阶段）。
- 不实现“章/回/节单位切换”开关（用户可通过自定义样式模板自行定义）。

## 验收标准

- outline/world 页面顶部展示作品工作台壳层与模块导航，且不再出现重复 header/布局冲突。
- 章节页与作品总览页中“第X章”展示不随分页/排序漂移（来自 display_order）。
- 草稿发布为章节：
  - 弹框提示将发布为第X章；
  - 若标题中包含冲突章号，必须展示修正前/后并强制修正后发布。
- 编号样式：
  - 支持全局默认 + 作品覆盖；
  - 中文数字支持到 1-9999；
  - 自定义样式模板必须包含 {N}，禁止换行；单位/文字由样式模板决定。

## 约束与风险

- 前端阶段会在需要时使用 limit=9999 拉取作品全量章节（章节规模 < 1000 的前提下可接受）。
- 发布链路后端当前会使用 draft.title 作为 chapter.title，前端若要保证最终标题正确，需要在 publish 前先更新草稿标题。
- 重排采用逐条 update 可能出现部分成功部分失败，需提供失败提示并刷新回服务器状态；后续可用后端事务/批量接口增强。

## 初步计划

1) 新增前端“章节编号样式 + 标题归一化工具”与本地存储。
2) outline/world 接入工作台壳层。
3) 章节号展示从 index+1 切换到 displayOrder/display_order。
4) 章节排序切换（URL 状态 + 前端排序）。
5) 草稿发布弹框：提示第X章 + 冲突修正 + 发布前更新草稿标题。
6) 章节重排：插入并顺延 + 同步修正 display_order 与标题前缀。
7) 补齐 vitest 用例。
