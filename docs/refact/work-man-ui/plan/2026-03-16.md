# 前端执行计划（work-man-ui）

## 阶段 0：基础能力（编号样式与标题归一化）

- 新增章节编号样式配置：全局默认 + 作品覆盖（localStorage）。
- 新增标题解析/归一化工具：
  - 解析/剥离用户输入中的章号前缀（第20章/第二十章/章节20/20. 等）。
  - 根据样式与系统 chapterNo 生成最终标题。
  - 冲突检测：userNo != chapterNo。
- 中文数字支持范围：1-9999。
- 自定义模板（高级）：仅允许 {N} 占位，必须包含 {N}，禁止换行；单位/文字由模板决定（例如可写“第{N}回”）。

编号结构约定：章节标题最终形态为“编号前缀 + 可选标题后缀”，默认编辑态引导用户只填写后缀。

验收：工具函数单测覆盖关键样例，且能提供 finalTitle/hasConflict。

## 阶段 1：outline/world 接入工作台壳层

- 将 `outline` 与 `world` 页从 mock 原型壳收敛到 `WorkWorkspaceLayout + WorkModuleSection`。
- 保留 mock 内容为占位，但移除 -m-8 与自建 header，避免重复导航与滚动冲突。

验收：outline/world 顶部出现工作台壳层导航，且页面结构与 chapters/drafts/characters 一致。

## 阶段 2：章节号展示口径统一

- 章节目录列表：显示 `displayOrder`，不再用 `index+1`。
- 作品总览页章节预览：显示前缀（样式 + displayOrder），不再用 `index+1`。

验收：分页/排序变化不会导致“第X章”漂移。

## 阶段 3：章节排序切换（前端）

- chapters 页面引入 `order=asc|desc` 的 URL 状态。
- 先做前端排序（按 displayOrder + id 稳定排序），后续后端支持排序参数后再升级为服务端排序。

验收：切换正序/倒序后列表顺序变化且 URL 状态正确。

## 阶段 4：草稿发布为章节（提示与修正）

- 发布弹框提示“将发布为第X章”。
- 若用户自定义标题包含冲突章号：展示修正前/后并强制修正。
- 为保证发布后章节 title 正确：publish 前先更新草稿 title 为 finalTitle，再调用 publish。

验收：发布出来的章节标题始终满足当前样式且章号正确。

## 阶段 5：章节重排（插入并顺延）

- 新增“调整章节号/调整位置”入口。
- 采用全量章节（limit=9999）重排：移除 + 插入 + 重新赋值 displayOrder=1..N。
- 同步修正 title 前缀（保留 suffix）。
- 逐条 update，失败则提示并刷新回服务器状态。

验收：第10章移动到第3章后，display_order 连续且标题前缀同步更新。

## 阶段 6：测试补齐

- 工具函数单测：strip/normalize/formatPrefix。
- 页面行为测试：排序切换、发布修正、重排 update payload。
